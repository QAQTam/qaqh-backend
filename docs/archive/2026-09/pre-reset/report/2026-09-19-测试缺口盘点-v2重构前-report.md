## 2. v2.0 重构面 × 测试缺口

### 2.1 Ringing v2.0（R1–R4：journal×3→events.jsonl、重连、内存订阅/lease、投影降级）

- **R1 存储合并**：要替换/删除的 `ringing/journal.rs`(255/6)、`journal_store.rs`(619/3)、
  `sequencer.rs`(212/4)、`persistence_policy.rs`(202/3)、`pending_store.rs`(476/4)、
  `outbox.rs`(214/4) 测试密度低；`latest/` checkpoint 目录语义（replaceable 身份 ×
  780 个/seed）**无专门测试**。
- **R2 重连**：唯一覆盖"断线→重连→流恢复"的是 `client/tests/lease_renegotiation.rs`
  的 2 条 `#[ignore]`（需 daemon 二进制）。缺：**in-process 的"重放视图 == live 视图"
  等价测试**（R2 核心验收），以及 `since_seq` 语义的边界测试（重叠丢弃/缺口检测/空流）。
- **R3 lease**：`lease_store.rs` 3 测；缺"双客户端并发订阅 + 断线移交"测试。
- **R4 投影降级**：`timeline_hub.rs` 788 行 0 直测（仅 `timeline_persist_deadlock_repro`
  间接触达）；`timeline_store.rs` 8 测。缺"投影删除后从 canonical log 重建 == 原投影"
  的对照测试（`timeline_rebuild.rs` 已证明"删 timeline 可从 messages.jsonl 重建"，
  但那是 v1 语义，R1 后事实源变了）。

### 2.2 Agent Loop / TurnCore（L0–L5）

- **L1 抽 `TurnCore::step`**：安全网是集成层（`ask_user_lifecycle` 1026 行、
  `permission_lifecycle` 764 行、`cancel_keeps_tool_results` 425 行、
  `inprocess_loop`、`hanging_tool_use_reload`）——它们覆盖粗但真实。
- **零直测且测试目录零引用的目标文件**：
  `turn_lap/admit.rs`(917，仅 `execute_admitted_batch` 经 test_api 被 1 个文件引用)、
  `loop_outcome.rs`(578)、`loop_dispatch_control/conversation/tool.rs`(合计 476)、
  `engine_input.rs`(331)、`engine_misc.rs`(117)、`types.rs`(498)、
  `state/lifecycle.rs`(365，仅 restart_prefix_cache 间接引用)、
  `spawn.rs`(147)、`paced_emitter.rs`(127)、`dashboard.rs`(17)。
- **编排语义（最危险）**：`admit.rs` 内 `serial_call_ids` 分区（并行 vs 串行）、
  `tool_call_order` 顺序回放、`apply_ordered_skill_effects`——全部无直测。
  证据：`serial_call_ids` 在测试目录仅出现一次且是空集
  （`cancel_keeps_tool_results.rs:247`，只覆盖全并行路径）；`tool_call_order`
  只作为参数传入、无顺序断言。
  09-19 spec §3 明确点名"loop 靠 `serial_call_ids` 手工编排"是结构性来源，
  `ToolCapabilities` 落地前必须先写**表征测试**锁住现状语义。
- **I2 exactly-once（L4）**：缺故障注入 harness（执行前写 intent → 崩溃 → 重启重放）。
  建议 failpoint 注入（env 触发）而非真 kill，与 `tool_outbox_locking.rs` 的
  fsync 计数钩子同款手法。
- **engine_tool.rs**(1127/5)：5 条直测只覆盖 `drain_bounded`（3）与展示投影（2）；
  执行/审批/分流全靠集成间接覆盖。

### 2.3 工具 SDK v1（09-19 spec：ToolName / ToolCapabilities / ExecuteBatch）

- **缺全表决策矩阵**：4 档 × 4 类别（read/write/exec/net）× 4 位置

- OS 沙箱是全新面（无实现无测试）：spec 建议 Linux landlock 先行，测试需按平台分层。

## 3. 横切基础设施缺口

1. **无 property/fuzz**：全仓零 proptest/quickcheck/arbitrary/cargo-fuzz。
   最合适的首批目标：`gate/sse.rs`（流式解码，10 测）、
   `apply_patch_engine/streaming_parser.rs`（404 行 / **0 测**）、
   `tool_parser.rs`（10 测）、audit v2 JSONL 解析（round-trip + 任意字节不 panic）。
2. **无覆盖率工具**：`cargo llvm-cov`/`tarpaulin` 均未安装。"1300+ 测试"目前无法回答
   "重构前后覆盖率是否守恒"。建议接入 llvm-cov 出 runtime/workspace 基线，
   作为 v2 迁移"行为不变"的量化对照。
3. **测试分层未定义**：5 个集成文件依赖真实 socket（`tiny_http`/`TcpListener`/
   `UnixListener`：mcp http_transport、runtime ask_user_lifecycle / permission_lifecycle /
   session_lifecycle、client lease_renew_timeout）；受限沙箱内必红（本次实测
   mcp 3 条 + ask_user_lifecycle 12 条）。另有 4 条 daemon-binary e2e 常年 `#[ignore]`。
   建议：三层（unit / socket / e2e）+ justfile recipe + README 说明，
   让"全绿"有明确前提。
4. **数据隔离依赖运行器**：多数集成测试用真实 `data_dir()`，靠外部
   `QAQH_DATA_DIR` 重定向（既有报告 §3 的 `.qaqh-testrun` 约定）；bare `cargo test`
   会写真实用户数据根。audit 已单测隔离（cfg(test) 重定向），建议推广同款。
5. **已知 flaky 未修**：`tool_outbox_locking.rs:193` 墙钟断言（既有报告 D-1，
   128ms 阈值 vs 实测 157ms）。v2 动 outbox 前必须先修，否则等价性验证被假红淹没。
6. **Windows 分支不可验证**：57 处 `cfg(windows)`（DPAPI/管道/shell/路径）。
   v2 沙箱是平台相关（landlock/seatbelt/MXC）→ 需 Windows 测试矩阵或至少交叉编译门禁。
7. **E2E 腐烂风险**：`daemon_full_session_lifecycle`、`lease_expiry_triggers_...` 等
   4 条 `#[ignore]` 从不运行。建议给"里程碑手动 tier"（just test-e2e），
   并在 R2/L4 验收时强制跑。

### 4.1 已落地：工具编排表征测试（2026-09-19）

`crates/qaqh-runtime/tests/tool_ordering_contract.rs`——6 个用例，5 轮重跑无抖动
（~0.5s/轮）。观察面是注册进测试 ToolManager 的进程内探针工具 `test_probe`
（记录 start/end/并发峰值 + rendezvous），不依赖 exec 子进程与墙钟阈值。

**锁定的 v1 现状语义**：

| # | 语义 | 用例 |
|---|---|---|
| 1 | 串行项严格在**全部并行项结束之后**才执行（并行组先跑、串行组后跑） | `mixed_batch_serial_group_runs_after_parallel_group` |
| 2 | 串行组按模型 `tool_call_order` 执行，与传入 `admitted` 顺序无关（夹具逆序送入） | `serial_group_keeps_model_order_not_input_order` |
| 3 | 并行组真并发、分批上限 = `MAX_PARALLEL_TOOL_WORKERS`(4)（rendezvous 确定性观测） | `parallel_group_is_bounded_and_actually_concurrent` |
| 4 | 并行组内结果按模型序回填（不按完成序） | `results_backfill_in_model_order_even_when_completion_order_differs` |
| 5 | 串行路径取消：已执行项保留结果、未执行项补 `Cancelled`、无 open tool_use | `cancel_after_first_serial_call_seals_the_rest` |
| 6 | skill effects 按模型序应用（不按完成序） | `skill_effects_apply_in_model_order` |

**新发现（需进 v2 spec 评审）**：

1. **跨组回填顺序 = 执行阶段顺序，不是全局模型序**。混合批
   `[并行A, 串行B, 并行C]` 的结果落地顺序是 `A, C, B`——并行组先回填、串行组
   随后。v2 若要求"结果一律按模型序落库"需显式变更并更新本契约。
2. **`TOOL_MANAGER` 是 `OnceLock`，`init_tools` 只有第一次生效**。测试夹具
   必须在 `AgentState::init`（其内部会 init_tools）**之前**注册额外工具，
   否则注册静默失效——这是 v2"工具注册表"重构时必须处理的隐式全局语义。

### 4.2 已落地：重放等价 harness（2026-09-19）

`crates/qaqh-runtime/tests/replay_equivalence.rs`——7 个用例，5 轮重跑无抖动
（~0.07s/轮）。全部在**公开 API 面**（`RingingHub::subscribe` / `replay_since` /
`replay_channel_since` / `with_persistence`）上断言，不触碰内部结构。

**锁定的 v1 重放语义**：

| # | 语义 | 用例 |
|---|---|---|
| 1 | reliable：live 订阅序列 == `replay_since(0)`（逐 event_id、按 stream_seq 升序） | `live_and_replay_agree_on_reliable_events` |
| 2 | 断点续传严格大于：`replay_since(k)` 只返回 seq > k（无重复、无缺口，k=0..=5 全扫） | `replay_since_cursor_is_strictly_greater_for_reliable` |
| 3 | replaceable：live 全量增量、重放只给当前值；**当前值不受 cursor 过滤** | `replaceable_replay_returns_current_value_unfiltered_by_cursor` |
| 4 | 重启等价：flush + 同 root 新 hub，重放 reliable 序列 == 重启前 live 序列 | `restart_preserves_reliable_sequence` |
| 5 | 频道级跨 seed 按 stream_seq 升序合并 | `channel_replay_merges_seeds_in_stream_order` |
| 6 | cursor 越窗 → `CursorExpired` + `RingingResetRequired`（reset→snapshot 路径） | `cursor_expired_signals_reset_path` |
| 7 | 新连接 `skip_reliable=true` 只回放 replaceable 当前值（历史交给 bootstrap 快照） | `fresh_connection_skips_reliable_history` |

**新发现（需进 v2 spec 评审）**：

1. **"live == replay" 只对 reliable 成立**：replaceable 在 live 是逐增量、
   在重放是当前值快照。v2 的 canonical `events.jsonl` 若把增量也落盘，
   R2 必须显式定义重放语义（grok 模式的 "replay-overlap dropped" 即此类问题）。
2. **两条重放路径对 replaceable 的 cursor 过滤不对称**：per-seed
   `replay_since` **不**过滤 replaceable 当前值（seq ≤ cursor 仍重放，客户端
   必须幂等）；频道级 `replay_channel_since` 仍按 `stream_seq > cursor` 过滤。
   v2 统一到 `since_seq` 时必须二选一并写进契约。
3. **无 cursor 新连接不回放可靠历史**（`skip_reliable=true`，防止幽灵
   running turn 先于 bootstrap 快照到达）——这是 R2 "阻塞请求重放" 之外的
   一条现存保护，迁移时不能丢。
