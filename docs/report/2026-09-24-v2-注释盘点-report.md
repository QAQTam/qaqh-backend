## 1. 为什么做

v2 硬切（bootstrap / 单流 / approvals / v1 路由全删）跨了几十个文件，注释与文档里
留了大量「指向已删除的路径/类型/文件」的指针。这类漂移没有编译期错误，只会在维护时
误导人——本轮的**第一个发现就是一条真回归**（见 §3）。

## 2. 方法（可复跑）

```bash
cd <repo>

# ① 指向已删除 wire 面的引用

# ③ 注释里的 file:line 指针是否还指向存在的文件
python3 - <<'PY'
import re
from pathlib import Path
names = {p.name for p in Path(".").rglob("*.rs") if ".git" not in p.parts}
for p in Path("crates").rglob("*.rs"):
    for i, line in enumerate(p.read_text().splitlines(), 1):
        for m in re.finditer(r"([A-Za-z_][A-Za-z0-9_\-]*\.rs):\d+", line):
            if m.group(1) not in names:
                print(f"{p}:{i}: {line.strip()[:100]}")
PY
```

## 3. 本轮修掉的

### 3.1 真回归：webui 事件流全 404（→ MR #355）

`crates/qaqh-webui-gateway/src/lib.rs` 的 `proxy_events` 仍把
`/__gateway/ringing/events/{channel}` 代理到已删除的 `/ringing/v1/events/{channel}`。
bootstrap / timeline / approvals 三个代理在硬切时都改了，**events 漏了** ⇒ 自单流硬切
（MR #352）起，浏览器侧所有投影事件流 404。

修法：路由改成 `/__gateway/ringing/sessions/{seed}/events` → v2 单流；路径由
`events_proxy_path()` 构造并加回归测试；前端改成「每 seed 一条 EventSource + 按
`stream_key` demux」。

### 4.2 file:line 指针（25 处，本轮已排除外部引用）

剩余的多指向**外部 crate**（`reqwest` 的 `request.rs`/`client.rs`）或测试夹具
（`src/a.rs:7`），不是本仓文件，属正常。**风险**：本仓文件行号会随重构漂移——
建议以后写指针时带函数名而不是行号（本轮已按这个原则改掉 `backend.rs:227` 那类）。

### 4.3 `RINGING_VERSION = 1` 仍标注内部 v1 形态的类型

`RingingEventBatch` / `RingingChannelSnapshot` / `capability` 仍是 v1 形状的**内部**
事件总线（timeline、orphan_seal、interaction body 入库都用它）。常量本身正确，但
「v1」这个词在新人眼里会被误读成「wire 上还有 v1」。建议后续重命名
（如 `LEGACY_DOMAIN_EVENT_VERSION`）或在常量上加一句说明。
