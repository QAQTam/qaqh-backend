## 3. 发现详情

### 3.1 D-1：`fact_seq` 崩溃恢复语义未冻结

- **现象（E2）**：#104 定义 `fact_seq` 为 per-session 单调递增且连续，但没有定义 seq 在 append 前还是 fsync 后分配，也没有定义 torn tail 截断后如何处理已分配但未提交的 seq。
- **根因（E3）**：架构层只给出不变量，字段级 schema/recovery 被下放给 #105；#105 尚未产出，因此当前无法判定“连续”是可实现还是只在无崩溃假设下成立。
- **影响面**：seq gap、重复 seq、snapshot 领先 log、恢复后二次终态，直接击穿 I2，并污染 replay/cursor。
- **复现设计**：在 `before_append`、`after_append_before_fsync`、`after_fsync_before_projection`、`after_projection_before_publish` 四个点注入崩溃；fixture 使用 `recovery/torn_tail.jsonl` 与 `crash_matrix.json`。
- **修复建议**：由 #105 冻结 seq 分配点、group commit、fsync barrier、torn tail 截断与 seq 复用/跳号规则；恢复只能追加恢复 fact，不得重写旧 fact。
- **验收清单**：`cargo test -p qaqh-runtime --test session_recovery_state_machine -- --test-threads=1`；seq gap=0、snapshot 领先=0、`SessionRecovered`=1。

### 3.2 D-2：复合 cursor 的 0..N 投影映射未冻结

- **现象（E2）**：#104 定义 `(log_id, fact_seq, projection_index)`，但没有逐 fact 给出 0..N reliable/replaceable/ephemeral 映射表，也没有定义同 fact 内 index 的稳定分配。
- **根因（E3）**：Fact 与 ProjectionEvent 是多对多关系，架构只给排序规则，没有给生成规则和去重规则。
- **影响面**：同 fact 多投影会被误去重；replaceable 可能错误推进 cursor；expiry/cross-session 可能静默映射。
- **复现设计**：同一 fact 生成 3 个 reliable projection；客户端从 `(log,7,0)` 重连；再覆盖 log_id mismatch、expired cursor、replaceable current value 和 v1 `Last-Event-ID` 跨 session。
- **修复建议**：在 #105 给出 fact→projection 映射表、`projection_index` 分配规则、dedupe key、cursor 推进条件和 `ResetRequired` 边界。
- **验收清单**：`session_fact_v2_cursor` 全部 C1-C3 场景通过；重复/缺口/跨 session 泄漏均为 0。

### 3.3 D-3：AuditStore 与 SessionStore 跨库一致性未冻结

- **现象（E2）**：#104 明确 `AuditStore` 是独立全局 hash chain，write/exec/net 两阶段 fail-closed；但未定义 audit intent/result 与 session fact append 的跨库顺序。
- **根因（E3）**：两个 durable store 没有共同事务，架构只给“先审计”原则，没有崩溃窗口和 quarantine 规则。
- **影响面**：可能出现无审计副作用、有审计但无终态、审计失败后继续执行高风险工具。
- **复现设计**：A1 intent 写失败、A2 result 写失败且副作用已发生、rotate/torn、secret 参数隐私断言。
- **修复建议**：定义 intent barrier → handler → result barrier → session terminal fact；result 失败进入 `IndeterminateQuarantined` + emergency sink，停止后续高风险写。
- **验收清单**：`session_fact_v2_permission_audit` 中 handler 调用为 0/1、audit 明文为 0、quarantine 记录为 1。

### 3.4 D-4：背压容量与 overflow 终态未冻结

- **现象（E2）**：#104 要求 actor/client/replay/progress/content 有界，但没有给出容量、丢弃、disconnect、reset 或拒绝规则。
- **根因（E3）**：背压被写成实现细节，尚未进入 schema/Gate 契约。
- **影响面**：unbounded channel、OOM、慢客户端拖死 actor、reliable fact 静默丢失。
- **复现设计**：B1 慢客户端、B2 mailbox 饱和、B3 replay buffer 超限、B4 progress flood。
- **修复建议**：冻结建议基线（mailbox 1024、connection 256、replay 16 MiB、progress 8 KiB/50 ms、fact 64 KiB、session content quota），并定义 overflow 终态。
- **验收清单**：`session_fact_v2_backpressure` 中 `dropped_reliable=0`、显式 reset/reject=100%、RSS 不随客户端数无界增长。

### 3.5 D-5：迁移、cutover、rollback 阈值未冻结

- **现象（E2）**：#104 要求双写对账、cutover 和 rollback，但没有对账字段、差异阈值、命令、删除 gate。
- **根因（E3）**：迁移被留在 P1 实现阶段，尚未进入 P0 契约冻结。
- **影响面**：在 diff/gap/rebuild 未归零时误删旧目录，rollback 后 transcript/seq 语义漂移。
- **复现设计**：M1 双写差异、M2 rollback、M3 二次迁移、M4 v1 cursor、M5 删除 gate。
- **修复建议**：定义 canonical_seq 对账键、差异阈值、cutover/rollback 命令、旧 writer 停止条件、删除 gate。
- **验收清单**：`session_fact_v2_migration` 全部 M1-M5 通过；任一非零指标下删除成功次数=0。

### 3.6 D-6：#105 spec 已评审但存在 blocking findings

- **现象（E2）**：#105 spec 已推送至 `d649ef7`（PR #107），独立评审完成；结论为 `blocking findings`，不是 `approved`。
- **根因（E2）**：spec 覆盖了 variant 与主字段，但 projection payload、policy ask/deny、recovery 终态、cursor expiry、GC、migration 和测试可执行性仍有 12 项 P0 阻断。
- **影响面**：架构冻结门禁不能关闭；若直接进入 P1，会把不可验证的 recovery/cursor/迁移语义带入实现。
- **复现设计**：`git fetch origin docs/105-session-fact-v2-schema`；读取 `docs/spec/2026-09-20-session-fact-v2-schema-spec.md`；按本报告 §7 的 BF-1..BF-12 逐项反证。
- **修复建议**：A 按 §7 逐项回写 spec，补精确 fixture/test/命令和终态矩阵；重新推送后由 B 复审。
- **验收清单**：BF-1..BF-12 全部关闭；每个 I1-I15 映射到精确测试文件、测试名、命令或 fixture；复审后才允许 `approved`。

### 3.7 D-7：P0-P6 Gate 可测性不足

- **现象（E2）**：Gate 使用“行为等价”“全绿”“无漂移”“可重复”等描述，没有统一命令和期望输出。
- **根因（E3）**：Gate 是路线图语言，不是测试契约。
- **影响面**：不同工程师对“通过”理解不同，无法作为合并门禁。
- **复现设计**：逐 Gate 检查是否存在可复制命令、fixture、故障注入、数值阈值和失败处理。
- **修复建议**：把本报告第 5 节矩阵作为 Gate 验收底稿，统一为命令 + fixture + 期望输出。
- **验收清单**：P0-P6 每阶段至少一条可复制命令和一个 fixture；所有“等价”均有规范化比较定义。

### 3.8 D-8：路径/TOCTOU 平台矩阵未冻结

- **现象（E2）**：#104 定义 `CanonicalPath`、`PathPolicy`、`FdPolicy`，但没有 symlink/device/FIFO/rename 的 OS 级算法与测试矩阵。
- **根因（E3）**：安全边界仍是目标类型，尚未落到 `openat/O_NOFOLLOW/fd-relative` 和 Windows device/UNC 规则。
- **影响面**：授权后替换 symlink、FIFO 阻塞、device 无界读、Windows 设备名绕过。
- **复现设计**：P1 symlink swap、P2 FIFO/device、P4 unsupported platform。
- **修复建议**：冻结 canonical identity、fd-relative 操作、unsupported fail-closed 策略和 Linux/Windows fixture。
- **验收清单**：`sandbox_path_matrix` 与 `path_toctou_race` 危险路径拒绝率=100%，工作区外写入=0。

### 3.9 D-9：跨仓 TUI 验收未固定 rev

- **现象（E2）**：#104 的 TUI 验收依赖外部 `qaqh-tui-app`，但没有在 #106 中固定被测 TUI commit。
- **根因（E3）**：I11/I12 和 P5 是跨仓契约，不是 backend 单仓可证明项。
- **影响面**：reducer 纯函数、wire 不泄漏存储、rebaseline 水位无法形成可复现 E1。
- **复现设计**：固定 backend/TUI rev，使用同一 wire/replay fixture 跑两端。
- **修复建议**：在 P5 开工前冻结 TUI rev、fixture 和命令；否则报告保持 E3。
- **验收清单**：同一事件序列任意重放 SessionModel hash 一致；展示路径 `serde_json::Value`=0；存储路径泄漏=0。

### 3.10 D-10：v1 基线全绿但不能替代 v2 验收

- **现象（E1）**：本轮运行 10 个相关测试目标、50 个用例，全部通过。
- **根因（E2）**：这些测试验证的是 v1 `stream_seq`、旧 WAL、旧 timeline 和旧审批生命周期。
- **影响面**：若把基线全绿误写成 v2 已通过，会跳过 canonical log、复合 cursor、durable ledger 和 OS sandbox 的真实验收。
- **复现设计**：见附录 B。
- **修复建议**：把本轮结果登记为迁移前基线；每个 P0-P6 Gate 必须新增 v2 测试，不能复用 v1 通过记录作为完成证据。
- **验收清单**：所有 I1-I15 至少有一条 v2 E1；报告明确区分 E1 基线与 E3 目标。

### I1 单 session 单 writer

- **不变量**：同一 session 的 `events.jsonl` 只能有一个 writer；跨进程 append 必须由 `events.lock` + OS file lock 仲裁，失败方返回 conflict，不得写入任何字节。
- **可执行验收**：两个独立进程同时打开同一 session；A 持锁时 B append 返回 `WriterBusy/Conflict`；A 释放后 B 可写；最终 JSONL 每行完整且 `fact_seq` 无交叉。
- **建议测试文件/模块**：建议新增 `crates/qaqh-store/tests/session_single_writer.rs`；`qaqh-store` 未抽取前放 `crates/qaqh-runtime/tests/session_store_single_writer.rs`。共享 helper：`crates/qaqh-runtime/tests/common/session_fact.rs`。
- **具体命令**：`cargo test -p qaqh-runtime --test session_store_single_writer -- --test-threads=1`
- **fixture/故障注入**：Rust 测试二进制自 re-exec，`QAQH_TEST_ROLE=writer-a|writer-b`；fixture 目录 `crates/qaqh-runtime/tests/fixtures/session_writer/`，含 `events.lock` 争用和进程 `SIGKILL`。
- **通过阈值**：50 轮双进程争用中，冲突返回率 100%；JSONL 解析成功率 100%；无半行、无重叠 seq、无同 seq 双 writer；持锁方崩溃后锁可回收。
- **反例**：两个进程都 append 成功；出现交叉/截断 JSON 行；只靠 `SessionManager.session_locks` 的进程内 `Mutex` 即宣称跨进程安全。
- **证据等级**：**E3（目标）**。E2 反证：`crates/qaqh-session/src/manager.rs` 只有进程内 `session_locks`；未发现 `events.lock`/OS file lock 的 v2 writer 实现。
- **是否 blocking**：**是（P1 Gate）**。

### I2 `fact_seq` 连续、snapshot 不领先

- **不变量**：`fact_seq` 在 append 前分配，崩溃恢复后从最后完整 JSONL 记录继续；投影 snapshot cursor 不得大于 canonical log cursor；torn tail 只截断到最后完整记录。
- **可执行验收**：在 append 前、append 后未 fsync、fsync 后未 apply、apply 后未 publish、投影写入中注入进程崩溃；重启后断言 `fact_seq=1..N` 连续、snapshot cursor ≤ log cursor、`.torn` 保留、`SessionRecovered` 恰好一次。
- **建议测试文件/模块**：建议新增 `crates/qaqh-store/tests/session_fact_recovery.rs`、`crates/qaqh-runtime/tests/session_recovery_state_machine.rs`。
- **具体命令**：`cargo test -p qaqh-runtime --test session_recovery_state_machine -- --test-threads=1`

- **不变量**：授权对象与执行对象是同一 canonical identity；symlink/device/FIFO/rename/open 边界按 `SandboxSpec` 处理；无法保证时 fail-closed。
- **可执行验收**：

  3. 授权后、open/rename 前替换 symlink 的 TOCTOU 竞态不得逃逸；
  4. Windows 设备名/路径拒绝；
  5. unsupported 平台 fail-closed。
- **建议测试文件/模块**：建议新增 `crates/qaqh-workspace/tests/sandbox_path_matrix.rs`、`crates/qaqh-workspace/tests/path_toctou_race.rs`；现有基线为 `file_shared.rs` 单元测试、`file_query.rs`、`file_mutate.rs`、`edit/tests.rs`、`apply_patch.rs`。

### 1. 六类边界设计

#### 1.1 复合 cursor

| 项 | 设计 |
|---|---|
| 预期终态 | `Live`，或 `ResetRequired { log_id, snapshot_cursor }`；非法/跨 session cursor 不得进入正常回放 |
| 核心规则 | canonical cursor 为 `(log_id, fact_seq, projection_index)`；同一 fact 的 `projection_index` 从 0 稳定递增；排序按 `(fact_seq, projection_index)` 字典序；`since_cursor` 为严格大于；replay/live 以完整 tuple 去重；`Replaceable/Ephemeral` 不推进 reliable cursor |
| 证据要求 | E2 基线：`crates/qaqh-runtime/tests/replay_equivalence.rs` 的 v1 用例；E3 新用例：`session_fact_v2_cursor.rs` + `fixtures/session-fact-v2/cursor/*.jsonl`；v1 映射 fixture 必须含 `(epoch, channel, stream_seq) → {session_id/seed, fact_seq, projection_index, delivery}` |
| 失败阈值 | 任一 cursor 逆序、同 fact 内 `projection_index` 非连续、replay/live 重复或缺口 > 0；跨 session 命中未 `ResetRequired`；过期 cursor 静默跳过事件 |

#### 1.2 崩溃恢复

| 项 | 设计 |
|---|---|
| 预期终态 | `Recovered`、`ReadOnlyUpgradeRequired`、`TurnInterrupted`、`ToolFinished::{Cancelled,Indeterminate}`、`InteractionExpired` |
| 核心规则 | `ToolIntent` 在执行前独立 fsync；每个 call 最终恰好一个 `ToolFinished`；非幂等工具不得自动重跑；torn tail 保留 `.torn` 后截断到最后完整行；`SessionRecovered` 只写一次；同 schema 未知 fact 进入 read-only/upgrade-required，不跳过继续解释 |
| 证据要求 | E2 基线：`cancel_keeps_tool_results.rs`、`timeline_rebuild.rs`、`timeline_stale_restore.rs`、`save_append_watermark.rs`、`tool_outbox.rs`；E3 新用例：`session_fact_v2_recovery.rs` + `fixtures/session-fact-v2/recovery/*.jsonl` |
| 失败阈值 | 每个 call 终态数不等于 1；崩溃注入后重复副作用 > 0；`SessionRecovered` 数 > 1；`fact_seq` gap > 0；未知 fact 后继续写入或解释后续 fact |

#### 1.3 权限安全

| 项 | 设计 |
|---|---|
| 预期终态 | `Allow + Executed`、`Deny + ToolRejected`、`Ask + InteractionRequested`、`InteractionResolved + Executed`、`EscalationApproved + Executed` |
| 核心规则 | 显式 `ToolCallContext`，禁止 thread-local 隐式 workspace/sandbox；规则引擎输出 allow/deny/ask/amend；OS sandbox 是最终边界；审批凭证只对单次 call/scope 有效；“记住决定”写 amend rule；路径授权对象与执行对象必须同一 canonical identity；symlink/device/FIFO/TOCTOU 在 open/rename/unlink 边界处理；unsupported 平台 fail-closed |
| 证据要求 | E2 基线：`permission_lifecycle.rs`、`permission_level_fail_closed.rs`、`trusted_folder_subtree.rs`、设备文件/符号链接 buglist；E3 新用例：`session_fact_v2_permission_audit.rs` + `fixtures/session-fact-v2/permission/*.json` |
| 失败阈值 | 未授权 write/exec/net 副作用 > 0；禁止路径漏放 > 0；TOCTOU 逃逸 > 0；同一审批执行次数 > 1；unsupported 平台 handler 调用 > 0 |

#### 1.4 审计

| 项 | 设计 |
|---|---|
| 预期终态 | `AuditedExecuted`、`RejectedBeforeExecution`、`IndeterminateQuarantined` |
| 核心规则 | `audit/` 是独立全局安全账本，不是 session projection；全局 seq/hash chain；write/exec/net 采用 intent→执行→result 两阶段 fail-closed；intent 审计 barrier 失败不得进入 handler；result 审计失败且副作用已发生时不得宣称回滚，必须进入 quarantine/emergency sink，停止后续高风险写操作，工具终态为 `Indeterminate`；参数只落 hash/bytes，不落明文，不进模型面 |
| 证据要求 | E2 基线：`crates/qaqh-workspace/tests/audit_ledger.rs`、`crates/qaqh-workspace/src/audit/v2.rs` 内联测试；`docs/spec/2026-09-19-审计账本v2-spec.md` §7 已明确 fail-closed 尚未落地；E3 新用例：`session_fact_v2_permission_audit.rs` + `fixtures/session-fact-v2/audit/*` |
| 失败阈值 | write/exec/net 无 intent 审计而执行 > 0；无 result 审计的终态 > 0；链校验 `HashMismatch/ChainBroken/SeqGap/TornTail` 漏报 > 0；审计/模型投影中出现参数明文 > 0；result 审计失败后继续执行高风险工具 > 0 |

#### 1.5 背压

| 项 | 设计 |
|---|---|
| 预期终态 | `Connected`、`DisconnectedResetRequired`、`CommandRejected`、`ResetRequired` |
| 核心规则 | actor mailbox 1024；per-connection queue 256；replay buffer 16 MiB；progress buffer 8 KiB/50 ms；单 fact 64 KiB；content 总量按 session 配额；reliable fact 不得静默丢弃；replaceable 只保最新值；ephemeral 可丢弃/合并；慢客户端达到高水位先断开并让客户端走 `ResetRequired`；磁盘配额不足先降级非关键 projection，再阻止高成本工具，不得 OOM |
| 证据要求 | E2 基线：`crates/qaqh-runtime/src/ringing/outbox.rs` 的 `reliable_fifo_then_replaceable_latest`、`backpressure_only_when_replaceable_exhausted`；当前行为是 `OutboxFull`，不是 v2 的 disconnect/reset；E3 新用例：`session_fact_v2_backpressure.rs` + `fixtures/session-fact-v2/backpressure/*.json` |
| 失败阈值 | `max_queue_depth > 配置上限`；`dropped_reliable > 0`；overflow 时 `reset_required == 0`；测试超时前 actor 无法响应心跳/命令；progress 窗口超过 8 KiB/50 ms；replay buffer 超过 16 MiB；OOM 或死锁 |

#### 1.6 迁移

| 项 | 设计 |
|---|---|
| 预期终态 | `CutoverComplete`、`CutoverBlocked`、`RolledBack` |
| 核心规则 | 先引入临时单 writer facade；旧 `messages.jsonl`、三频道 journal、timeline/offload 继续双写观测；对账使用 `canonical_seq`；双写差异、seq gap、投影 rebuild 失败任一超阈值即禁止 cutover；cutover 前旧 writer 不得停止；rollback 只切回旧读路径；删除旧目录必须过删除 gate |

| 失败阈值 | 双写语义差异 > 0 仍 cutover；`fact_seq` gap > 0；replay/live 不等价；rollback 后 transcript/seq 语义差异 > 0；diff/gap/rebuild failure 非零时删除旧目录；迁移二次执行产生重复 fact/content |
