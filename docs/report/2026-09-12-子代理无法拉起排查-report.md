## 2. 分析方法与证据链

1. **静态链路核清（E2）**：模型工具 → `handle_spawn_subagent`（`qaqh-subagent/src/lib.rs:377`）→ 宿主探测 `host()` → `QaqhService::spawn_subagent`（`host_impl.rs:21-42`）→ `AgentRegistry::spawn_subagent_inprocess`（`registry.rs:270-343`）→ `run_subagent_actor`（`actor.rs:131`）→ collect 线程注入（`lib.rs:573-700`）。宿主安装点唯一：`qaqh-daemon/src/server.rs:164`。父 actor 工具表含 `spawn_subagent`（`agent.rs:60-62` 注册器 + `spawn.rs:92-103` 白名单）。

## 3. 发现 D-1：子代理不继承主代理工作区（BUG-05 的子代理受害面）

### 3.1 现象

子代理内使用相对路径工具（grep/read/exec 相对 cwd）时锚定 daemon 进程 cwd 而非主代理工作区；行为与 BUG-05 相同，但根源在 spawn 时的继承判定。

### 3.2 根因（E2）

`qaqh-subagent/src/lib.rs:430-440`：

```rust
// 子代理继承主代理的工作区：CURRENT_WORKSPACE 为空/`.` 时不传，宿主侧
// 同样跳过继承（子 actor 退化为 daemon cwd）。
let parent_workspace = qaqh_workspace::CURRENT_WORKSPACE
    .read()
    .unwrap_or_else(|e| e.into_inner())
    .clone();
let workspace = if parent_workspace.is_empty() || parent_workspace == "." {
    None
} else {
    Some(parent_workspace)
};
```

`handle_spawn_subagent` 运行在**派生工具线程**上（与 BUG-05 同一执行模型），`CURRENT_WORKSPACE`（进程全局）在 daemon 中恒为空 → `workspace=None` → `host_impl.rs:30` 的 `filter` 跳过 `set_cwd` → 子代理 `meta.cwd` 不落盘。实测探针子代理 `6939f380/meta.json`：**`cwd: None`**（E1）。正确取值应为 TLS 优先的 `qaqh_workspace::current_workspace()`（actor 线程/其 scope 恢复线程上有值）。

### 3.3 影响面

子代理内全部相对路径工具行为同 BUG-05 §3.3；子代理自身的工作区边界检查、exec 缺省 cwd 均退化为 daemon 进程 cwd。 BUG-05 修复（ActorToolScope 携带 workspace）落地后，本处只需把读取源改为 `current_workspace()` 即随之修复；若 BUG-05 未修，仅改此处无法恢复子代理内工具的正确解析。

### 3.4 复现（E1）

1. 主会话设置工作区 A（`workspace.set`）。
2. 调用 `spawn_subagent`（任意任务）。
3. 读子 seed 的 `~\.qaqh\sessions\{sub_seed}\meta.json` → `cwd` 为 `null`/缺失（期望 A）。
4. 子代理内 `exec pwd` → 返回 daemon 进程 cwd（期望 A）。

实测记录：步骤 3 已完成（`6939f380` cwd=None）；步骤 4 未执行（探针子代理为纯文本任务，已回收）。

### 3.5 修复建议

`lib.rs:432` 的 `qaqh_workspace::CURRENT_WORKSPACE.read()` 改为 `qaqh_workspace::current_workspace()`（随 BUG-05 方案 A 的 push/pop TLS 通道自动正确）。独立于 BUG-05 的附加价值：即便将来 handler 再次运行在无 TLS 线程，也应显式经主代理上下文传参——建议长期把「父会话工作区」作为 `ToolCallCtx` 的显式字段传递，而非读全局/线程状态。
