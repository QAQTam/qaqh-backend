## 1. 今晚做了什么（一段话）

Q41 会话「最后命令导致前后端双崩」的假设被证伪：真凶是 RingingV2 读面 **attach 活锁**——
bootstrap 取读前水位、订阅时判 `since < current_seq` 即掐流、广播无回放尾、客户端 Reset 零退避，

daemon 泵被快照读洪泛拖死）。11/03 P3-D 退役把 9/20 建的 replay window 连坐删除是回退源头。
修复 = owner 侧有界回放尾环 + `attach_after` 原子 attach（先 grab receiver 后切环）+ Lagged 改环内
追帧；真缺口（尾覆盖外/epoch 失配）保留原 `ringing.resync_required` wire 形状。**零契约漂移**：
freeze 闸本机实测 `LTS API surface unchanged`，change-policy `无冻结面改动`（self-test 18/18）。

## 3. 守卫测试语义（改动前必读）

- `emit` 定序纪律：**先入环、后广播**；`attach_after`：**先 grab receiver、后读环**。两注释在
  owner.rs，破坏任一序都会开回活锁的门。环预算 2048 帧/4MB。
- 游标语义按契约头注（events.rs `SessionEventFrame` 文档）：**exclusive**，`seq >= cursor` 补发，
  重帧由转发水位 `last_seq` 跳过 + 客户端幂等吸收。
- 守卫④钉住 resync 兜底不被顺手删。改 SSE 路径的人请保持它绿。
