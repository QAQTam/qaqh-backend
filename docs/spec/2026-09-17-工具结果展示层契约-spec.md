## 1. 问题陈述

### 1.1 现状：展示层被迫传原始 JSON

`qaqh-runtime/src/timeline.rs:118` 的 summary 投影：

```rust
pub(crate) fn tool_summary(output: &str) -> String {
    output
        .lines()
        .next()                      // ← 取第一行
        .unwrap_or("")
        .chars()
        .take(qaqh_types::TOOL_SUMMARY_MAX_CHARS)
        .collect()
}
```

`exec` 工具的 `output` 第一行**就是整个 JSON blob**，于是 `summary` 变成被
`TOOL_SUMMARY_MAX_CHARS` 从中间截断的 JSON 字符串，例如：

```
{"status":"completed","command":"bash ...","exit_code":0,"output":"总计 79764\ndrwxr-xr-x ...
```

### 1.2 量化（真实会话 `5e34cca4`，2500 次工具调用）

| 工具 | 调用次数 | summary 是原始 JSON 的比例 | summary 均值 |
|---|---|---|---|
| **exec** | 1907 | **1900 / 1907（99.6%）** | 460 B |
| read | 312 | 0 | 47 B |
| edit | 116 | 110（94.8%） | 80 B |
| todo_update | 65 | 65（100%） | 318 B |
| todo_write | 44 | 44（100%） | 177 B |
| write | 17 | 17（100%） | 105 B |
| spawn_subagent | 8 | 8（100%） | 291 B |
| **合计** | **2500** | **2160（86.4%）** | 375 B |

**86.4% 的工具 summary 是原始 JSON。** 同时同一份数据被重复三遍：
exec 的 `summary`(460B，内含 output 前缀) + `output`(614B) + `progress`(794B)。

### 1.3 下游代价：TUI 侧 268 行补偿代码

`qaqh-tui/src/app/render_transcript.rs:1045-1312` 存在 **268 行纯 JSON 解析**、
6 处 `serde_json::from_str`，全部为补偿本缺陷而写：

| 函数 | 行号 | 本质 |
|---|---|---|
| `shell_meta_from_raw` | 1293 | **从 JSON 里抠 `exit_code` / `truncated` / `status`** |
| `extract_shell_output_text` | 1152 | 从 JSON 抠 output 文本 |
| `exec_command_summary` | 1255 | 从 `args_json.argv` 重建命令串 |
| `extract_path` | 1098 | 从 args_json 抠 path |
| `pretty_json_output` | 1187 | 美化 JSON 输出（兜底） |
| `format_args_preview` | 1050 | args 预览 |

`push_tool_card` 本体 856 行，靠 `tool.name == "exec"` 之类的字符串分支分派。

### 1.4 根因

原文 §8.4 的 `ToolDisplay` 只有两个字段：

```rust
pub struct ToolDisplay {
    pub summary: Option<String>,
    pub diff: Option<String>,
}
```

**装不下** exec 的 `exit_code` / `duration` / `status` / `stdout` / `stderr`。
所以工具作者只能把结构化数据塞进 `output` 字符串，timeline 再取第一行当 summary。

## 2. 参照：两家同类产品如何做

### 2.1 Codex：模型投影与展示投影**分开**，且展示侧字段类型化

- 模型侧：`ToolOutput::to_response_item()` → `ResponseInputItem`，保留 `formatted_output`。
- 展示侧：core `TurnItem` → app-server `ThreadItem::CommandExecution`
  （`app-server-protocol/src/protocol/v2/item.rs:289`）：

```rust
CommandExecution {
    id, command: String, cwd, source: CommandExecutionSource,
    status: CommandExecutionStatus,
    command_actions: Vec<CommandAction>,   // ← shell 语义解析
    aggregated_output: Option<String>,
    exit_code: Option<i32>,                // ← 类型化
    duration_ms: Option<i64>,              // ← 类型化
}
```

**关键事实**：展示侧**不含** `formatted_output` / `stdout` / `stderr`。
验证：`grep -rn formatted_output codex-rs/tui/src/` **零命中**——TUI 从不消费模型格式化串。

`CommandAction`（`v2/item.rs:128`）在工具层就把 shell 命令解析成语义：

```rust
pub enum CommandAction {
    Read      { command, name, path },
    ListFiles { command, path },
    Search    { command, query, path },
    Unknown   { command },
}
```

**三层截断，常量不同**：

| 层 | 位置 | 上限 |
|---|---|---|
| 采集 | `core/src/exec.rs:79` | 1 MiB |
| 模型投影 | `models-manager/src/model_info.rs:141` | 10k tokens（切中间） |
| **UI 渲染** | `exec_cell/render.rs:33` | **5 行**（用户 shell 50 行） |

UI 截断发生在 **wrap 之后、按视口行计**（`truncate_lines_middle`），非按逻辑行。

流式为 **begin / delta / end 三元事件**，靠 `call_id` 关联；`delta` 带
`stream: ExecOutputStream{Stdout,Stderr}`（`protocol/src/protocol.rs:3590`）；
终态 `aggregated_output` **覆盖**流式预览。

未覆盖的工具走 `fallback_transcript_cell`（`tui/src/thread_transcript.rs:198`），
**保证结果不静默丢失**。

### 2.2 Grok：一份结果三投影，TUI 永不碰原始 JSON

`crates/common/xai-tool-runtime/src/tool.rs:246`：

```rust
pub struct TypedToolOutput {
    pub tool_id: ToolId,
    pub value: Value,                                    // 宿主 / 审计
    pub model_output: Vec<ContentBlock>,                 // 给模型（保证非空）
    pub chat_completion_output: Option<ToolChatCompletionResponse>,  // 给前端
}
```

TUI 侧每工具一个类型化 block（`blocks/tool/execute.rs:18`）：

```rust
pub struct ExecuteToolCallBlock {
    pub command: String,          // 完整真相（搜索/复制/导出）
    pub error: Option<String>,    // None = 成功
    pub description: Option<String>,
    pub output: Option<String>,   // 增量流式
    pub started_at: Option<Instant>,
    pub elapsed_ms: Option<i64>,  // ← 耗时
    pub bash_mode: bool,          // ← 是否用户发起
    pub header_display: Option<String>,  // ← 显示态与真相分离
}
```

**验证**：`xai-grok-pager/src/scrollback/` 全目录搜
`args_json|raw_json|serde_json::Value|params` → **零命中**。转换发生在
`acp/tracker.rs`，TUI 只吃类型化 block。

### 2.3 共性（本文采纳的原则）

| 原则 | Codex | Grok | 本文对应条款 |
|---|---|---|---|
| 结果字段**类型化**，不塞 JSON | `exit_code: i32` | `elapsed_ms: Option<i64>` | §4.2 |
| **投影分离**（模型 / 展示 / 宿主） | `formatted_output` vs UI item | `value`/`model_output`/`chat_completion_output` | §3 |
| 命令**解析成语义**再给 UI | `CommandAction` | per-tool block | §4.3 |
| 流式带**流标识** | `stream: Stdout\|Stderr` | `ToolProgress::Text` | §5 |
| **显示态与真相分离** | `display_lines` vs `raw_lines` | `header_display` vs `command` | §4.4 |
| 未覆盖工具**兜底** | `fallback_transcript_cell` | `OtherToolCallBlock` | §4.5 |

## 3. 投影职责（修订原文 §8.2）

原文 §8.2 的投影表保留，新增一列「是否进 wire」：

| 投影 | 消费者 | 禁止内容 | 进 wire |
|---|---|---|---|
| `output` | 宿主、审计、后续工具 | 不保证直接发给模型 | 否（仅保留现有 `TimelineTool.output`） |
| `model` | provider tool result | 不包含内部 source | 否 |
| `display` | timeline、TUI、client | 不参与模型决策 | **是** |
| `metrics` | telemetry、审计、TUI | 不包含敏感参数正文 | **是**（原文说「未迁移 client 可忽略」） |

## 4. ToolDisplay 扩展（修订原文 §8.4）

### 4.1 目标结构

```rust
pub struct ToolDisplay {
    /// 单行人类可读摘要。**禁止是 JSON**（见 §6 硬性规则 H11）。
    pub summary: Option<String>,
    /// 统一 diff（文件变更类工具）。
    pub diff: Option<String>,
    /// 标题行素材：TUI 直接渲染，不必解析 args。
    pub header: ToolHeader,
    /// 正文素材：按工具类别给出结构化形态。
    pub body: ToolBody,
    /// 运行信息。
    pub metrics: ToolMetrics,
}
```

### 4.2 正文与运行信息

```rust
pub enum ToolBody {
    None,
    /// 通用文本（read / grep / glob / 大多数工具）。
    Text { text: String, truncated: bool },
    /// 统一 diff（edit / apply_patch / write）。
    Diff { unified: String, files: Vec<String> },
    /// shell 执行（exec / bash / pwsh）。
    Shell {
        stdout: String,
        stderr: String,
        exit_code: Option<i32>,
        truncated: bool,
    },
    /// 表格（todo_list / todo_write / todo_update / skills）。
    Table { columns: Vec<String>, rows: Vec<Vec<String>> },
}

pub struct ToolMetrics {
    /// 执行耗时（毫秒）。
    pub elapsed_ms: Option<u64>,
    /// 是否由用户直接发起（对齐 Codex `ExecCommandSource::UserShell`
    /// 与 Grok `bash_mode`）。影响 TUI 的默认展开与截断行数。
    pub user_initiated: bool,
}
```

### 4.3 ToolHeader

```rust
pub enum ToolHeader {
    /// 文件类（read / write / edit / glob / apply_patch）。
    Path { path: String, op: PathOp },
    /// shell 类（exec / bash / pwsh）。command 为完整可复制命令。
    Shell { command: String },
    /// 检索类（grep / web_search / web_fetch）。
    Query { query: String, scope: Option<String> },
    /// 其余工具。label 为人类可读单行。
    Other { label: String },
}

pub enum PathOp { Read, Write, Edit, List, Patch, Delete }
```

**约束**：`ToolHeader` 由工具作者在 descriptor / output 投影中声明，
**不得**由 timeline 层从 `args_json` 反推。对齐 Codex `CommandAction`
在工具层解析、Grok 在 tracker 层转换的做法。

### 4.4 显示态与真相分离（采纳 Grok）

对可折叠工具，展示层需同时提供：

- **真相**：`Shell.command` / `Path.path` 等完整值——供搜索、复制、导出。
- **显示态**：`summary` 或 `header` 的折行形态——仅供标题行渲染。

TUI **不得**修改真相字段用于显示（当前 TUI 的 `truncate_str` 调用点应只作用于显示态）。

### 4.5 兜底要求（采纳 Codex）

任何 `ToolBody` 为 `None` 且 `summary` 也为 `None` 的工具，
timeline 层必须填入有界文本兜底，**不得**产生空白卡片。
对齐 Codex `fallback_transcript_cell` 与 Grok `OtherToolCallBlock`。

## 5. 进度模型修订（修订原文 §9.1）

原文 §9.1 的 `ToolProgress::Text { stream, text }` 定义正确，
但 **wire 层 `TimelineTool.progress: String` 把它拍平了**——`stream` 信息丢失。

修订：`TimelineTool` 新增可选字段承载流标识：

```rust
// qaqh-domain/src/timeline.rs
pub struct TimelineTool {
    // …现有字段不变…
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub display: Option<ToolDisplay>,   // §4.1
}
```

**终态覆盖语义**（对齐 Codex）：`body` 一旦进入终态（工具 seal），
client 应丢弃 `progress` 预览并以 `body` 为准。

## 6. 硬性规则（追加原文 §12）

原文 §12 的 10 条保留，追加：

| ID | 规则 |
|---|---|
| H11 | **`summary` 不得是 JSON**。序列化后首字符为 `{` 或 `[` 的 summary 视为违规，由测试守护。 |
| H12 | shell 类工具必须在 `ToolBody::Shell` 中给出 `exit_code`，**不得**只放在 `output` 字符串里。 |
| H13 | `ToolHeader` 必须由工具作者声明，timeline 层不得从 `args_json` 反推（防止每个 client 各写一套解析）。 |
| H14 | `ToolDisplay.metrics.elapsed_ms` 必须来自 `ToolExecutionMetrics.elapsed`（原文 §8.3），不得生成后丢弃（呼应原文 §12 第 8 条）。 |
| H15 | 任何工具都必须能投影出非空 `summary` 或 `body` 或兜底文本（§4.5）。 |

## 7. 迁移与 wire 兼容（修订原文 §11）

原文 §11 的「在 client/TUI 完成新字段接入前，不得删除旧 `ToolResult` 字段」**保留**。
本次新增字段一律走 `#[serde(default, skip_serializing_if = ...)]`：

1. `TimelineTool.display` 为 `Option`，旧 client 忽略即可。
2. 旧字段 `summary` / `output` / `progress` / `diff` **不删除**，但其产出规则按 §6 收敛。
3. `summary` 从「output 第一行」改为「工具声明的 canonical summary」——
   这是**行为变更**，需评估：现有 client 若依赖旧 summary 形态需同步。
4. 落地顺序建议：
   - 阶段 1：`ToolDisplay` 类型 + `exec` 一个工具试点（P0）。
   - 阶段 2：timeline 投影接入 `display`，同时按 H11 修正 `summary` 生成。
   - 阶段 3：TUI 接入 `display` 后删除其 JSON 解析补偿代码（见 §1.3 清单）。
   - 阶段 4：其余工具分批迁移。

## 8. 验收标准（追加原文 §14）

- `summary` 为 JSON 的工具在测试中判失败（H11）。
- `exec` 的 `display.body` 为 `Shell` 且 `exit_code` 非空（H12）。
- `display.metrics.elapsed_ms` 与 `ToolExecutionMetrics.elapsed` 一致（H14）。
- TUI 接入后，`render_transcript.rs` 中 §1.3 列出的 6 个解析函数**全部删除**，
  且 TUI 侧 `serde_json::from_str` 调用数从 6 降为 0（工具展示路径）。
- 回归：全量 `cargo test -p qaqh-runtime` / `-p qaqh-workspace` / `-p qaqh-domain` 通过。
