## 1. 目标与非目标

目标：

1. 任何 client（TUI / WinUI）**不需要解析工具原始 JSON** 即可完整展示工具结果。
2. 模型投影、展示投影、运行元数据来自同一 canonical outcome，不产生第二事实源。
3. 展示字段类型化、可按工具维度演进、对旧 client 与旧 server 双向兼容。
4. 迁移可分批落地并可独立回滚，每一批都有硬性验收。

非目标（v1）：

- 不引入按需全文回取端点（`timeline.tool_output` 延后，见 §9）。
- 不区分展示用的 stdout / stderr（合流，见 §4.3）。
- 不引入 `Table` 展示变体（todo 面板只消费 canonical summary，见 §9）。
- 不承诺 stdout / stderr 的真实交织顺序（需要 pipe 层序号，另立 v2）。
- 不改动模型可见文本的语义；`model` 投影与现状一致。

## 2. 投影模型与数据流

```text
TypedTool::run(ctx, &args)
  -> Output
  -> ToolOutput::model_blocks / summary          （模型投影）
  -> ToolOutput::display(&args)                  （展示投影：header/body/summary/diff）
  -> ToolOutcome { status, output, error, model, display, metrics }
  -> runtime 适配器（唯一映射点）
       -> qaqh_types::ToolResult                 （模型面 + legacy 字段）
       -> TimelineTool { summary/output/diff/progress, display? }
       -> Ringing ToolFinished（metrics 扩展）
       -> audit.csv
```

约束：

- 展示投影与模型投影必须来自**同一个** `ToolOutcome`（H6）。
- `display` 由工具作者声明（structural fields），`metrics` 与进度计数由框架填充（H4）。
- `TimelineTool` 旧字段（`summary` / `output` / `diff` / `progress` /
  `progress_truncated`）在 v1 期间全部保留。

## 3. 类型定义

### 3.1 归属与依赖方向（本文的硬性决策）

| 层 | 位置 | 说明 |
|---|---|---|
| SDK 内部类型 | `qaqh-workspace::tool_api` | `ToolDisplay` / `ToolHeader` / `ToolBody` / `ToolMetrics` / `PathOp` |
| wire 类型 | `qaqh-domain::timeline` | `TimelineToolDisplay` / `TimelineToolHeader` / `TimelineToolBody` / `TimelineToolMetrics`；随 `ts` feature 导出 |
| 映射 | `qaqh-runtime::timeline` | `project_display(&ToolDisplay) -> TimelineToolDisplay`，唯一映射点 |

- `qaqh-domain` **不得**依赖 `qaqh-workspace`（现有依赖方向单向）。
- `qaqh-workspace` 不得把内部类型直接序列化进 wire；跨层必须经过映射并做兼容测试。
- TUI/WinUI 只依赖 wire 类型（TS 生成物），不得依赖 workspace 类型。
- 若未来想让两层复用同一类型，需单独评审 `qaqh-workspace → qaqh-domain` 的 R-4 边界，
  不在本规格授权范围内。

### 3.2 SDK 内部类型（`qaqh-workspace::tool_api`）

```rust
pub struct ToolDisplay {
    /// 单行人类可读摘要。禁止 JSON（H1）。
    pub summary: Option<String>,
    /// 统一 diff（文件变更类工具）。
    pub diff: Option<String>,
    pub header: ToolHeader,
    pub body: ToolBody,
    /// 由适配器填充；工具实现不得决定取值（H4）。
    pub metrics: ToolMetrics,
}

pub enum ToolHeader {
    None,
    /// 文件类（read / write / edit / glob / apply_patch / delete / copy_range）。
    Path { path: String, op: PathOp },
    /// shell 类（exec）。command 为完整可复制命令。
    Shell { command: String },
    /// 检索类（grep / web_search / web_fetch）。
    Query { query: String, scope: Option<String> },
    /// 其余工具。label 为人类可读单行。
    Other { label: String },
}

pub enum PathOp { Read, Write, Edit, List, Patch, Delete }

pub enum ToolBody {
    None,
    /// 通用文本（read / grep / glob / web / process / journal / todo 系列等）。
    Text { text: String, truncated: bool },
    /// 文件变更（edit / apply_patch / write）。
    Diff { unified: String, files: Vec<String> },
    /// shell 执行（exec）。output 为**已归一化的合流文本**（见 §4.3）。
    Shell { output: String, exit_code: Option<i32>, truncated: bool },
    /// 子代理（spawn_subagent）。仅供面板/巡检路由，不是通用 JSON 逃生口。
    Subagent { name: String, seed: String },
}

pub struct ToolMetrics {
    /// 执行耗时（毫秒）。
    pub elapsed_ms: Option<u64>,
    /// 本次调用产出的展示文本字节数（UTF-8，截断后）。
    pub output_bytes: u64,
    pub retry_count: u32,
    /// 别名/MCP 解析后的实际工具名；无别名时 = descriptor.name。
    pub effective_tool_name: Option<String>,
    /// 调用来源是否为用户直接发起（ToolCallSource 属于用户侧）。
    pub user_initiated: bool,
}
```

### 3.3 Wire 类型（`qaqh-domain::timeline`）

所有新增字段一律 `#[serde(default, skip_serializing_if = ...)]`，全部可选。

`TimelineTool` 的增量为：

```rust
pub struct TimelineTool {
    // ……现有字段全部不变……
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub display: Option<TimelineToolDisplay>,
    /// 进度流标识。值域："stdout" | "stderr" | "mixed"；未知值按 None 处理。
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub progress_stream: Option<String>,
    /// 本次调用累计观测到的进度字节（含被丢弃/裁剪的部分，截断前）。
    #[serde(default, skip_serializing_if = "is_zero")]
    pub progress_bytes_total: u64,
}

fn is_zero(v: &u64) -> bool { *v == 0 }
```

前向兼容：

- `TimelineToolHeader` / `TimelineToolBody` 使用 **internally tagged + Unknown**：
  旧 client 遇到新变体反序列化为 `Unknown`，走 §4.5 的兜底，而不是整块解析失败。
- `progress_stream` 用开放字符串而非封闭枚举，未知值按 `None` 处理。
- 删除/改名已有字段或变体属于 breaking change：必须新开 v2 规格，
  并至少保证一个发布周期内新旧字段双写。

### 3.4 映射规则（`qaqh-runtime`）

| 内部 | wire | 规则 |
|---|---|---|
| `ToolDisplay.summary` | `TimelineTool.summary` + `display.summary` | 双写；缺失/非法时走 §4.1 的 fallback |
| `ToolDisplay.diff` | `TimelineTool.diff` + `display.diff` | 双写 |
| `ToolHeader::None` | `display.header = None` | 不产出空壳变体 |
| `ToolHeader::{Path,Shell,Query,Other}` | `display.header` | 1:1 映射 |
| `ToolBody` | `display.body` | 1:1 映射 |
| `ToolMetrics` | `display.metrics` | 1:1；`elapsed_ms` 来自 `ToolExecutionMetrics.elapsed` |
| `ToolError` | `TimelineFailure { code, message }` | `code` 直接映射，`message = detail`（有界） |
| progress 计数 | `progress_stream` / `progress_bytes_total` | 由 progress 通道统计，不解析文本 |

缺失映射（例如工具未提供 header）不视为错误：投 `None`，client 走兜底。

### 3.5 结构化终态 `outcome`（#336 P2）

`ToolDisplay` / `ToolResultDisplay` / `TimelineToolDisplay` 增加可选
`outcome`，让 client 不再从 `summary` 文本猜 `[OK]`、`timeout` 或终态：

```rust
pub struct ToolResultDisplayOutcome {
    pub state: ToolResultDisplayOutcomeState,
    pub exit_code: Option<i32>,
    pub duration_ms: Option<u64>,
    pub output_bytes: Option<u64>,
    pub truncated: Option<bool>,
}

pub enum ToolResultDisplayOutcomeState {
    Succeeded,
    Failed,
    Cancelled,
    TimedOut,
    Backgrounded,
    Unknown, // 未知 wire 值，保证前向兼容
}
```

规则：

- `state` 由 `ToolStatus` + `ToolErrorKind` 单点派生；exec 的 `timed_out` /
  `cancelled` 由 `ExecOutput` 显式声明，不从 summary 反推；
- `exit_code` / `truncated` 由 typed body 派生；
- `duration_ms` / `output_bytes` 由框架 metrics 填充；legacy 结果没有
  metrics 时保留已存在的 outcome 值，不得用 0 覆盖；
- 字段全部 optional / 可忽略，旧 client 继续读 `summary` / `body`；
- live、messages 归档、timeline 快照三条路径必须保留同一 outcome；
- P3 的 stdout/stderr 分离见 §3.6；v1 旧 `Shell` body 继续保留。

### 3.6 v2 stdout/stderr 分离 `Streams`（#336 P3）

exec 的展示 body 新增：

```rust
ToolBody::Streams {
    stdout: String,
    stderr: String,
    exit_code: Option<i32>,
    truncated: bool,
    interleaved: bool,
}
```

wire 侧同名变体落在 `ToolResultDisplayBody::Streams` 与
`TimelineToolBody::Streams`。

规则：

- `interleaved = false`：两条流已经分开，不承诺 stdout/stderr 的真实交织顺序；
- 旧 `Shell { output, exit_code, truncated }` 与 `TimelineTool.output` 继续保留，
  旧 client 遇到未知 `streams` 变体时必须完整回退旧字段；
- exec 的 display-only stdout/stderr 不进入模型 JSON（`ExecOutput` 用
  `#[serde(skip)]` 承载），模型面仍只读原有 `output`；
- stdout/stderr 各自按 display body 上限截断，`truncated` 是两条流与模型输出
  截断状态的并集；
- `exit_code` 在 `Streams` 中继续携带，避免旧 client 只能从 summary 猜退出码。

## 4. 不变量（H 系列）

| ID | 规则 | 守护 |
|---|---|---|
| H1 | `summary` 不得是 JSON。判定为**解析式**：`serde_json` 能解析且是 object/array 即违规；截断的 `{` 开头文本同样违规。 | 后端单测 + fixture 回归 |
| H2 | shell 类工具必须在 `ToolBody::Shell` 或 v2 `ToolBody::Streams` 给 `exit_code`；前台 completed 必须非空，backgrounded/cancelled 允许为 `None` 但字段必须存在。 | exec 单测 |
| H3 | `ToolHeader` 由工具作者声明（`ToolOutput::display(&args)`），timeline/前端不得从 `args_json` 反推。 | 代码评审 + 映射测试 |
| H4 | `display.metrics` 与进度计数由框架填充；工具实现提供的值被覆盖。 | 映射测试 |
| H5 | 每个工具必须至少声明非空 `summary` 或非 `ToolBody::None` 的 body；timeline 对两者都空的结果填 `"{name} · {state}"` 兜底，禁止空白卡片。 | 全工具 fixture 遍历 |
| H6 | 模型投影、展示投影、metrics 必须来自同一个 `ToolOutcome`。 | 集成测试（同 call_id 比对） |
| H7 | wire 新增字段必须 `Option` + `serde(default)`；新枚举变体必须落 `Unknown`。 | 兼容 fixture（旧 client 反序列化新 JSON） |
| H8 | 丢弃必须可见：`body.*.truncated`、`progress_truncated`、`output_bytes` 与实际展示一致。 | 快照测试 |
| H9 | `display` 必须进 timeline **快照**（翻页/重连后不退化），而非只在 SSE 实时帧。 | 快照/重连测试 |
| H10 | 展示字段不得包含凭据与环境变量正文；命令/路径只回填用户已输入的内容。 | 安全扫描 + 评审 |
| H11 | legacy summary 只有在**非 JSON** 时才可沿用；否则用合成兜底，不得再取模型输出首行。 | 迁移期测试 |
| H12 | `progress_bytes_total` 是累计观测字节（含丢弃/裁剪前），`output_bytes` 是最终展示文本字节；两者不得混用。 | 计数单测 |
| H13 | wire 工具名/字段名/枚举 tag 遵循本文；规范名 `^[a-z][a-z0-9_]*$` 且 ≤ 64 字符；动态工具名经规范化并保留 `display_name`。 | descriptor 校验 + 动态注册测试 |
| H14 | v1 `Shell` body 只给一个合流 `output`；v2 可用 `Streams` 分离 stdout/stderr，但不得让 client 从文本重拼。 | 类型评审 |
| H15 | `Cancelled` / `Timeout` 是终态但非失败：必须与 `Error` 区分；三者都可恢复、不得升级为 fatal。 | 执行器单测 |
| H16 | `display` 缺失（旧 server / 未迁移工具）时，client 必须完整回退到旧字段渲染，不得部分解析新字段。 | 前端回退测试 |

旧编号映射：H1 ← 旧 H11；H2 ← 旧 H12（放宽 backgrounded/cancelled）；H3 ← 旧 H13；
H4 ← 旧 H14；H5 ← 旧 H15（改为可证伪）。

## 5. 进度契约（修订 09-15 §9）

### 5.1 字段语义

- `progress`：有界尾部文本（现状 16 KiB 上限），到达序合流。
- `progress_truncated`：**流式**语义——尾部缓冲曾丢弃更早前缀。与
  `body.*.truncated`（最终输出被截断）是两件不同的事，两者都保留。
- `progress_stream`：`"stdout" | "stderr" | "mixed"`；`mixed` 表示一次进度帧
  内混合（v1 的 exec 逐帧发送单一流，正常只会出现前两者）。
- `progress_bytes_total`：本次调用累计观测字节，**包含**被有界 channel 丢弃
  和被尾部裁剪的字节；实现点在 `ExecProgressSender`（现在已有 `dropped_bytes`，
  增加 accepted 计数即可）。

### 5.2 归一化责任（v1.1 修订：按可实现的方式定稿）

- 终态 `body.output`：后端负责 ANSI 剥离（`ExecOutput` 现状已有）+ 行内 `\r`
  覆盖归一化（含 `\r` 的行取最后一个非空覆盖段，纯 `\r` 行丢弃）；
  `model` 文本**不因此改变**。已实现于 `exec/display.rs::normalize_carriage_returns`。
- 流式 `progress`：**保持原始字节序透传（含 `\r` 与 ANSI）**。已发送的字节无法
  撤回，后端强行归一化会丢信息或需要重传协议；覆盖语义由 client 在自己累积的
  缓冲上渲染（TUI 现有 `apply_bash_progress` 保留：ANSI 剥离、`\r\n`、`\r` 覆写，
  跨 chunk 边界语义以 client 累积缓冲为准）。
- 由此 Running → Sealed 允许一次视觉重排（progress 原始态 → body 归一化态），
  这是有意行为：终态以 `body` 为准（§5.3）。

### 5.3 终态覆盖

`body` 进入终态（工具 seal）后，client 必须丢弃 `progress` 预览并以 `body`
为准（对齐 Codex）；SSE 与快照使用同一份 `body`。

## 6. 需求矩阵（TUI 消费面 → 字段）

代码落点：

- SDK 内部类型：`qaqh-workspace/src/tool_api.rs`；注册表：`manager.rs::register_display`；exec 投影：`exec/display.rs`；其余内置投影：`display.rs` 与 `qaqh-subagent/src/lib.rs::project_subagent_display`
- wire 类型：`qaqh-domain/src/timeline.rs`；唯一映射：`qaqh-runtime/src/timeline.rs::wire_display`
- 投影调用点：`agent/engine_tool.rs`（live 终端两处）、`ringing/timeline_rebuild.rs`（rebuild，用归档 args 重放同一投影）
- 已验证：`cargo test -p qaqh-workspace` 全绿、`cargo test -p qaqh-runtime` 全绿（`ask_user_lifecycle` 需本地端口，沙箱外验证 15/15）、`cargo check -p qaqh-domain --features ts` 通过、clippy 无新增告警

MCP 命名规则：模型面/卡片 `name = mcp__<server>__<tool>`；`display.metrics.effective_tool_name = <tool>`（server 侧原名）。
MCP per-server fallback：`display.header = Other { label: <完整注册名> }`，`display.body = None`（不与 `output` 双写），`display.summary = "args [...]"`（最多 3 个 primitive 参数）。
客户端可因此删除通用 args 考古器；未注册的静态工具仍完整回退 H16。
静态工具没有别名时保持 `None`，client 必须显示卡片 `name`。

实现注意：`display` 由 runtime 通过 `qaqh_workspace::runtime::project_tool_display` 查找工具作者投影后填充；
无可用 manager（部分纯单元/离线重建场景）时保持 `None`，client 按 H16 完整回退旧字段。

### 7.1 summary 投影算法（Phase A 起生效）

```text
project_summary(card):
  1) outcome.display.summary（存在且通过 H1）        → 采用
  2) legacy result.summary（存在且通过 H1）           → 采用（未迁移工具）
  3) 合成 "{effective_tool_name} · {state_label}"     → 兜底（有界、非 JSON）
```

- `state_label` 取 `succeeded / failed / cancelled / running / backgrounded`。
- 步骤 3 保证 Phase A 起 86.4% 的 JSON summary 立即消失，即使工具尚未迁移；
  代价是未迁移工具的标题先退化为"名称 + 状态"，正文仍由旧字段提供。
- H1 的解析式判定要同时覆盖"完整 JSON"和"被 512 字符截断的 JSON 前缀"。
