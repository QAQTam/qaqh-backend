# 审计账本 v2 —— 时间/行为/对象三可追溯设计

> **状态**：核心已落地（v2 写入 + 哈希链 + 校验 + 双写 + 拒绝路径记账），
> 留存/签名/查询 CLI 属 P2/P3 待排期（见 §7）。
> **代码**：`crates/qaqh-workspace/src/audit/`（`mod.rs` v1 CSV + `v2.rs` 主账本）
> **测试**：`cargo test -p qaqh-workspace`（单测 13 条 + 端到端 `tests/audit_ledger.rs`）

## 1. 背景与目标

工具侧审计账本（v1 `audit.csv`）只回答"哪个工具、成功与否、耗时多少"。
商业审计要求账本同时可回答三件事：

| 维度 | 问题 | v2 字段 |
|---|---|---|
| **时间** | 何时发生？顺序可信吗？丢过记录吗？ | `ts`（RFC3339 纳秒 UTC）+ `ts_mono_ns`（单调时钟）+ `seq`（跨重启连续）+ `boot_id` |
| **行为** | 谁、在哪个会话、哪次调用、被允许还是被拒绝、结果如何？ | `actor` + `tool` + `decision` + `result.error_code` |
| **对象** | 对什么做了操作？操作前后是什么状态？ | `objects[]`（路径 + before/after 内容指纹） |

非目标（本期）：WORM 介质、远程 SIEM 转发、Ed25519 签名、留存自动清理。

## 2. 现状与缺口（实测）

来源：`~/.config/qaqh/audit.csv` 1338 条记录分析（2026-09-19）。

| 缺口 | 证据 | v2 处置 |
|---|---|---|
| 失败无法归因 | 111 条 `fail` 无错误码 | `result.error_code`（取自 `ToolResult.error.code` / `ToolError::code()`） |
| 主体缺失 | `user` 列硬编码 `agent` | `actor{user, session, call_id, sandbox}`；`user` 为 OS 登录名 |
| 决策链缺失 | `PermissionChallenge` 携带 session/call_id/risk 但用完即丢 | `decision.outcome`（`GrantKind` 随凭证传递）+ 拒绝事件落账 |
| 对象只有路径 | `files` 列 | `objects[]` + before/after 指纹（复用 `file_state` LF 规范视图 hash） |
| 无完整性 | 任何一行可被增删改且无感 | SHA-256 哈希链 + `verify_ledger` |
| 时间不可验证 | 无序号/单调时钟 | `seq` + `ts_mono_ns` + `boot_id` |
| 权限过宽 | `audit.csv` 0644 | 创建即 0600（Unix；Windows 依赖 ACL） |
| 写入静默失败 | `log::error!` 后继续 | 双写返回 `Result`，调用方必须上报 |

## 3. 设计

### 3.1 文件布局与双写

```
{data_dir}/audit.csv             # v1：15 列（8 旧列 + 7 扩展列），旧消费方按列索引不受影响
{data_dir}/audit/v2.jsonl        # v2：主账本（活动段）
{data_dir}/audit/v2.jsonl.{1..3} # v2 rotate 代（只 rename，不 truncate）
{data_dir}/audit/v2.jsonl.torn   # 崩溃撕裂尾行侧车（证据保留）
```

- 每条 `AuditEntry` **同时**写 CSV 与 v2；两边都尝试，任一失败返回
  `AuditError`（`Csv` / `V2`），由调用方 `log::error!` 上报。
- CSV 扩展列（尾部追加）：`session, call_id, category, error_code,
  output_bytes, retry_count, decision`。

### 3.2 记录模型（JSONL 一行一条）

```json
{"schema":"qaqh.audit/v2","kind":"tool_call","seq":12043,"boot_id":"2f1c-1a2b...",
 "ts":"2026-09-19T07:45:35.130514574+00:00","ts_mono_ns":3821455000000,
 "actor":{"kind":"agent","user":"qaqtamsy","session":"d9a1a320","call_id":"call_01J...","sandbox":false},
 "tool":{"name":"edit","action":"run","category":"write","effective_name":null,"permission_level":3},
 "decision":{"outcome":"auto"},
 "args":{"hash":"9f2c…（sha256）","bytes":1843},
 "result":{"status":"ok","error_code":null,"elapsed_ms":8,"output_bytes":312,"retry_count":0},
 "objects":[{"kind":"file","path":"/…/render/mod.rs",
             "before_sha":"1a2b…","after_sha":"44cd…"}],
 "prev_hash":"sha256:77aa…","hash":"sha256:e0d1…"}
```

### 3.3 词汇表（闭集，读侧未知值容忍）

| 字段 | 取值 |
|---|---|
| `kind` | `tool_call`（到达终态）｜`tool_rejected`（授权/前置检查拒绝，未执行） |
| `decision.outcome` | `auto`｜`user_approved`｜`sandbox_auto`｜`challenge_required`｜`rejected` |
| `result.status` | `ok`｜`error`｜`partial`｜`cancelled`｜`backgrounded` |
| `tool.category` | `read`｜`write`｜`exec`｜`net` |
| `objects[].kind` | `file`（当前）｜`process`/`net`/`mcp`/`skill`/`session`（预留） |

`GrantKind`（`authorization.rs`）是 `decision.outcome` 的单一来源：
MCP D5 快路径与策略自动放行 = `auto`，审批凭证 = `user_approved`，
子代理沙箱自动批准 = `sandbox_auto`。

### 3.4 完整性：链、恢复、轮转

- **链**：`hash = sha256(prev_hash + "\n" + canonical_json(record 去掉 hash 字段))`；
  `prev_hash` 指向上一条的 `hash`，链头为 `""`。canonical_json 由 serde
  按结构体字段声明顺序序列化（无 map 遍历），跨进程可重算。
- **seq**：跨重启连续。进程内缓存链状态；重启后从账本尾部（活动文件 →
  rotate 代）恢复 `(seq, hash)` 续接。
- **撕裂尾行**：崩溃导致的无 `\n` 结尾尾行在下次 append 时移入 `.torn`
  侧车（证据保留），活动文件截断到最后一个完整行后继续。
- **轮转**：活动文件 ≥ 4 MiB 时 `v2.jsonl → .1`，旧代顺移（最多 3 代）。
  链与文件边界无关，`verify_ledger` 按 `.3 → .2 → .1 → 活动` 逐段校验。
- **校验**：`verify_ledger(root) -> VerifyReport` 检查 schema、逐条 hash、
  `prev_hash` 衔接、`seq` 连续性；问题枚举：
  `TornTail` / `Unparsable` / `SchemaMismatch` / `HashMismatch` /
  `ChainBroken` / `SeqGap`。`truncated_history=true` 表示最老一代已被
  轮转截断（事实标注，非错误）。

### 3.5 隐私与访问控制

- **参数永不落明文**（workspace v2 spec 硬规则 9）：只有 `args.hash`（SHA-256）
  与 `args.bytes`；`decision.reason` 截断至 512 字符。
- 对象只落路径与内容指纹（file_state 的 LF 规范视图 hash，非原始字节 hash）。
- 账本文件创建即 0600（Unix）；Windows 依赖目录 ACL（P2 补显式 ACL）。
- 账本不进模型面、不进 bootstrap summary（沿用 v1 语义）。

## 4. 接线点

| 位置 | 职责 |
|---|---|
| `execution.rs::execute_authorized` | 成功/失败终态记账（含对象 before/after 指纹）；六类前置拒绝（session/workspace/resource 不匹配、取消、PLAN 阻断、prepare 失败、manager 不可用）记账 |
| `execution.rs::execute_with_context` | 授权拒绝（`challenge_required`/`rejected`）与参数解析失败记账 |
| `execution.rs::audit_rejected` | 拒绝事件统一构造（kind=`tool_rejected`，error_code 显式给出） |
| `authorization.rs::GrantKind` | 授权路径随凭证传递（`AuthorizedToolCall::grant()`） |
| `manager.rs::extract_files_affected` | 对象路径单一口径（派发前 before 快照 + finalize 统计共用） |
| `file_state.rs::last_hash` | 对象 before/after 指纹来源 |
| `lib.rs::ToolError::code` | 错误码单一来源（与 `into_result` 同源） |

## 6. 兼容性

- CSV 前 8 列语义不变（`result` 列由 status 派生：`ok|backgrounded → ok`，
  其余 → `fail`；`files` 列 = 对象路径 `;` 连接）。
- v1 `append_audit` 签名由 `()` 变为 `Result<(), AuditError>`——调用方
  必须显式处理（当前唯一调用方：`execution.rs`）。
- v2 读侧对未知字段/未知枚举值容忍；`schema` 字段是格式判定唯一入口。
- **v2 从启用时刻起记**（seq 从 1 开始）；启用前的历史保留在 v1 CSV
  （含 rotate 代），两边以时间戳关联。
- **单测隔离**：crate 内单测（`cfg(test)`）账本重定向到
  `{temp}/qaqh-audit-unit-test-{pid}/`，绝不写真实用户账本；集成测试
  需自行钉住 `QAQH_DATA_DIR`（`tests/audit_ledger.rs` 已示范）。
