## 0. 边界

- 这些开关只用于 backend/daemon 的真实进程测试，不进入 Ringing wire。
- 开关在 daemon 启动时读取；除 `QAQH_TEST_LEASE_TTL_MS` 外，运行中不重读。
- 所有注入必须保持正常协议形态：只改变触发时机或结果，不新增 TUI 专用旁路。
- 一次性故障（SSE 终止、timeline gap、permission-deny、ask-dismiss）消费后即
  失效，避免客户端重连或后续交互陷入永久失败循环；`*-hang` 变体刻意保持持续。
- 未列出的 `QAQH_TEST_*` 都不是公开契约。

## 1. 交互路径

### 1.1 plan review

| 变量 | 值 | 语义 |
|---|---|---|
| `QAQH_TEST_PLAN_REVIEW` | `1` / `true` / `yes` / `on` | 每个 turn 的 round 0 在调用 provider 前生成真实 `PlanReviewRequested` 并挂起，等待正常 `PlanReviewRespond` |
| `QAQH_TEST_PLAN_REVIEW_CONTENT` | 任意字符串 | 可选，覆盖默认 plan 正文 |

验收：

- `PlanReviewRequested.interaction_id` 为 `test-plan-review-{turn_id}`；
- `review_type == "plan"`；
- approve / reject 均走现有 `handle_plan_response` 并继续下一轮；
- 不触发时行为零变化。

### 1.2 permission / ask 故障

| 变量 | 值 | 语义 |
|---|---|---|
| `QAQH_TEST_INTERACTION_FAULT` | `permission-deny` | 收到 `ToolPermissionRespond` 后强制按拒绝处理；一次性 |
|  | `permission-hang` | permission 响应命令永不返回 ack，供 TUI 超时/清理路径；持续 |
|  | `ask-dismiss` | 收到 `InteractionAskRespond` 后改写为 `InteractionAskDismiss`；一次性 |
|  | `ask-hang` | ask 响应命令永不返回 ack，供 TUI 超时/清理路径；持续 |

组合方式：

- permission / ask 的请求由 TUI fake provider 正常产生；
- 断流使用 §2.1 的 `QAQH_TEST_SSE_TERMINATE`，再配合 channel/scope 选流；
- ack 挂起/超时也可单独使用 §3.1。

注意：`*-hang` 只冻结该条 HTTP command handler，不冻结 daemon 主循环；测试
结束时必须终止 daemon 进程，不能等待该请求自行返回。

## 2. SSE / timeline

### 2.1 `ringing.stream_terminated`

| 变量 | 值 | 默认 | 语义 |
|---|---|---|---|
| `QAQH_TEST_SSE_TERMINATE` | `lagged` 或任意稳定 code | 未设置 | 注入一帧 `ringing.stream_terminated` 后关流；`lagged` 自动带 `skipped` |
| `QAQH_TEST_SSE_TERMINATE_SCOPE` | `channel` / `timeline` / `any` | `channel` | 作用流 |
| `QAQH_TEST_SSE_TERMINATE_CHANNEL` | `control` / `conversation` / `tool` | 任意 | 仅作用于指定 channel SSE |
| `QAQH_TEST_SSE_TERMINATE_SKIPPED` | 非负整数 | `7` | `code == "lagged"` 时的 `skipped` |

行为：

- 一次性：第一条命中的 SSE 连接收到终止帧，后续重连恢复正常；
- `channel` 流载荷含 `channel`；
- `timeline` 流载荷含 `seed`；
- 终止帧之后不再发数据帧。

### 2.2 timeline gap

| 变量 | 值 | 语义 |
|---|---|---|
| `QAQH_TEST_TIMELINE_GAP` | `1` / `true` / `yes` / `on` | 一次性**丢弃** timeline 流的第一条可投递 entry，不发任何替代帧、也不关流；客户端 cursor 因此停在 `after`，下一条真实 entry 是 `after + 2`，由客户端自己的 `cursor + 1` 判定触发 `TimelineGap -> recover_gap` |

验收：

- 不编造 `timeline_seq`：丢弃的是真实 entry，下发的也都是 journal 中真实 entry；
- 只统计归属本 seed 且通过 cursor/dedup 判定的 entry；foreign seed 必须在 gap
  分支之前被过滤；
- **不依赖 journal 深度**：只丢一帧，后续 entry 照常下发；不再要求「至少两条
  可投递 entry」，也不再在注入后关流；
- **不重复下发已送达 entry**：客户端 cursor 不推进，收到的下一帧必然 `> cursor`，
  且该帧只下发一次（注入后关流会让客户端用同一 cursor 重连并二次收到同一帧，
  这正是本钩子必须避免的形态）；
- 客户端必须调用 `/ringing/v1/sessions/{seed}/timeline` 重新取权威快照；
- 重连后 hook 已消费，不得再次跳号；
- 不猜测缺失历史。

## 3. 会话与命令

### 3.1 command ack

| 变量 | 值 | 语义 |
|---|---|---|
| `QAQH_TEST_COMMAND_ACK` | `hang` 或毫秒整数 | `hang` 永不返回 ack；整数延迟指定毫秒后继续正常处理 |
| `QAQH_TEST_COMMAND_ACK_CHANNEL` | `control` / `conversation` / `tool` | 可选，只影响指定 channel |
| `QAQH_TEST_COMMAND_ACK_COMMAND` | `interaction` / `permission_response` / `ask_response` / `all` | 默认 `interaction`，只命中 permission/ask 响应；测试通用 command 面时显式设 `all` |

用途：验证 TUI 在途命令超时、取消、退出清理不依赖 ack。默认谓词避免
`permission-hang` / `ask-hang` 意外冻结同 channel 上的其它命令。

### 3.2 session 404

| 变量 | 值 | 语义 |
|---|---|---|
| `QAQH_TEST_SESSION_404_SEED` | seed 或 `*` | 命中的 bootstrap / approvals / timeline snapshot / timeline SSE 返回 HTTP 404 |

用途：验证 U-29 只有在明确 404 时把子代理收口为 `Closed`。
