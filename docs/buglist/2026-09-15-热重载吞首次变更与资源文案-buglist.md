## 事实与证据（07）

### 复现

1. daemon 已在运行；
2. 改 `config.toml` 的 `[lsp]` 段（`enabled = false` → `true`，并新增 `[lsp.servers.rust-analyzer]`）；
3. 观察 `qaqh-daemon.log`：出现 `[config] file change detected …; reloaded`，**但不出现** `[lsp] hot-reload applied`；
4. 再改一次（哪怕只改一个无关数字：`idle_shutdown_secs 120 → 121`）→ `[lsp] hot-reload applied (added=["rust-analyzer"] …)` 立刻出现。

真机日志（epoch 秒）：

```
[1789479567] INFO  qaqh_runtime::service: [config] file change detected (…/config.toml); reloaded
              ← 第 1 次改动：只有"检测到"，没有任何 apply
[1789479622] INFO  qaqh_runtime::service: [config] file change detected (…/config.toml); reloaded
[1789479622] INFO  qaqh_runtime::service: [lsp] hot-reload applied (added=["rust-analyzer"] updated=[] removed=[] kept=0 conn)
[1789479622] INFO  qaqh_runtime::service: [mcp] hot-reload applied (…)
              ← 第 2 次改动：两个 reloader 同时生效（各自的 receiver 都吞了第 1 次）
```

### 机制

`crates/qaqh-runtime/src/service.rs`：

| 位置 | 事实 |
|---|---|
| `:729` `spawn_mcp_reloader` / `:772` `spawn_lsp_reloader` | 两个 reloader 同款骨架 |
| `:733-735` / `:775-777` | `if rx.changed().await.is_ok() { rx.borrow_and_update(); }` ← **前置消费一次变更** |
| `:736` / `:778` | `while rx.changed().await.is_ok() { … }` ← 真正处理变更的循环 |
| `:741` / `:783` | 循环体内已有 `if published.<sec> == manager.config() { continue; }`（对"无变化"幂等） |

`qaqh_config::watch::subscribe()`（`crates/qaqh-config/src/watch.rs:34`）返回的 receiver，
其 `version` 已标记为**当前版本**。因此那次前置 `changed()` 等到的**不是**启动期快照，
而是**用户启动后的第一次改动**；随后 `borrow_and_update()` 把它丢弃。

即：该守卫的意图（"跳过启动期那次"）在 `subscribe()` 语义下不成立——它必然吞掉一次真实变更。

### 影响

- 用户改 `[lsp]`/`[mcp]` 配置后**看不出任何效果**，且日志里"reloaded"字样会造成"已生效"的误判（本次实操中先误判为 TOML 解析回退默认，排查后才定位）。
- 每 daemon 生命周期**只咬一次**（两个 reloader 各一次）；之后正常。
- 文件轮询器本身正常：`spawn_config_file_poller`（`service.rs:~807`，1.5s mtime）每次都正确触发 `reload_from_disk` → `publish`。

### 修复建议（未实施）

直接进 `while`，去掉前置消费——"无变化"已由循环体内的 `published == manager.config()` 兜住：

```rust
let mut rx = qaqh_config::watch::subscribe();
tokio::spawn(async move {
-   if rx.changed().await.is_ok() {
-       rx.borrow_and_update();
-   }
    while rx.changed().await.is_ok() { … }
```

若确实需要"跳过启动期发布"，应改为**显式比较 manager 当前配置**（本就是下方那个 `continue` 的语义），而不是吞掉一次 `changed()`。

## 事实与证据（08）

### 复现

```
mcp → list_servers:
  codegraph: connected, 1 tool(s), 0 resource(s)
  context7:  connected, 2 tool(s), 0 resource(s)

mcp → list_resources(server="context7")     # 该 server 已 connected
  ## context7 (stdio)
    (no resource list available — server not connected yet; call read_resource to connect, or check list_servers)

mcp → list_prompts(server="context7")       # 同一 server、同一时刻
  [context7] (declares prompts capability but lists none)
```

即：**同一个已连接的 server**，prompts 分支措辞正确，resources 分支却把它报成"没连上"。

### 机制

`crates/qaqh-mcp/src/resources.rs:176-191`：

```rust
let (resources, templates) = match &conn {
    Some(conn) => (conn.cached_resources(), conn.cached_resource_templates()),
    None => (None, None),                       // 未连接 / 无连接
};
match resources.filter(|resources| !resources.is_empty()) {
    Some(resources) => { …逐行输出… }
    None => section.push_str(
        "\n  (no resource list available — server not connected yet; …)"),  // ← 三种含义共用一句
}
```

`cached_resources()`（`crates/qaqh-mcp/src/connection.rs:563`）返回 `state.resources`，而
`connection.rs:412-424` 在**成功拉到空列表时也存 `Some(Arc::new(vec![]))`**：

```rust
Ok((Ok(resources), Ok(templates))) => {
    state.resources = Some(Arc::new(resources));   // 空列表也是 Some
```

于是 `.filter(|r| !r.is_empty())` 把「已连接但空」重新变成 `None`，
与「未连接」「`resources/list` 失败」（`connection.rs:430-432`，此时确实保持 `None`）**共用同一句文案**。

对照正确范本：prompts 分支（`resources.rs:490`）区分了「声明了但为空」与「未声明该能力」两种措辞。

### 修复建议（未实施）

三层语义分开（顺带修"能力位"缺失）：

```rust
match &conn {
    None => "(not connected yet — call read_resource to connect, or check list_servers)",
    Some(conn) => match conn.cached_resources() {
        Some(r) if !r.is_empty() => { …逐行… }
        Some(_) => "(connected — server lists no resources)",
        None => "(no resource list available — resources/list failed; see daemon log)",
    },
}
```

若要完全对齐 `list_prompts` 的"是否声明 capability"分支，需在连接态里额外缓存
`initialize` 回包的 capability 位（当前**未缓存**，仅在日志里出现过）。
