# buglist（2026-09-19）— 设备文件 / FIFO / 符号链接的工具边界

> 状态口径：`open` / `fixed（工作区，待提交）` / `fixed @{commit}` / `verified` / `wontfix @{commit}` / `wontfix`。
>
> 发现来源：read/write/edit 边界专项探查（2026-09-19）。
> 本条目**未单开 report**（证据自足并逐条内联于下）。
> 环境：Linux 沙箱，uid 1000，`/dev` 在该沙箱内可写（普通宿主系统非 root 不可写）。
> 复现方式：外部探针经 `qaqh_workspace::execution::execute_with_context` 走真实工具链路
> （`ToolCtx::admitted`，Level 4；另跑 Level 3 对照）。

## 结论定性

**不是恶意 bug，也不只是文件系统特性**，分三类：

1. **文件系统特性**（本身无错）：`rename` 替换目标 inode、`fs::write` 跟随符号链接、设备文件无 EOF、FIFO 无写者时 `open` 阻塞。
2. **工具契约缺陷**（要修）：read 不区分普通文件/设备/FIFO；write/edit 与 apply_patch/journal 对符号链接的写入语义相反；授权对象与执行对象不一致；read 无界且不响应 cancel。
3. **策略未定**（需要 owner 拍板）：最终组件是符号链接时，是"拒绝写"还是"穿透写目标"。

## 证据链

### 1. read 设备/FIFO（BUG-01）

```text
### read /dev/null
  success=true  content="L1: "
### read fifo          → timeout 5 后仍未返回（exit=124）
### read /dev/zero     → 400MB 虚拟内存上限下报 "out of memory"
```

- `file_query.rs:80` 只查 `is_dir()`；`:124` 直接 `std::fs::read_to_string` 全量读；
  `READ_MAX_LINES/READ_MAX_CHARS` 在读完**之后**才截断（`file_shared.rs:7-8`）。
- `read` 的 `default_timeout = 15s`（`file_query.rs:310`）只写入 `ToolCallCtx.timeout_secs`，
  `read_one` 不检查 timeout/cancel；`drain_bounded`（`engine_tool.rs:957-987`）等
  `tool_done` → 阻塞读会挂住整个 turn。
- 空文件/`/dev/null` 返回 `"L1: "`：`split('\n')` 对空串给出 1 行（BUG-07）。

### 2. write `/dev/null`（BUG-02）

- `file_mutate.rs:195` → `atomic_write`（`file_shared.rs:40-68`）：
  `parent/.null.qaqh-<pid>-<nonce>.tmp` + `rename(temp, /dev/null)`。
- 普通宿主系统 `/dev` 不可写 → `WRITE_FAILED`（无害）；**本沙箱 `/dev` 可写** → 会真的把
  设备节点换成普通文件。为避免破坏沙箱，**未实际执行** `write /dev/null`；结论来自
  同一 temp+rename 机制（该机制已在 symlink 上实测，见下）。
- 权限层：`/dev/null` 解析后在工作区外 → L3 需审批、L4 自动放行。

### 3. 符号链接（BUG-03）

工作区内 `link -> target`：

```text
edit link   → [OK] ... replaced 1 occurrence
              link[is_symlink=false body="HELLO\n"]  target[body="hello\n"]
write link  → [OK] ... | write
              link[is_symlink=false body="WORLD\n"]  target[body="hello\n"]
apply_patch → [OK] apply_patch — applied: 1 file(s)
              link[is_symlink=true body="PATCHED\n"] target[body="PATCHED\n"]
```

- `write`/`edit` 走 `atomic_write` → rename 替换最终组件（链接被摧毁、目标不动）。
- `apply_patch` 引擎走 `std::fs::write`（`apply_patch_engine/mod.rs:342/462`）→ 穿透链接；
  `journal` replay 同样 `fs::write`（`journal.rs:97/294`）。
- 外部链接对照：L3 `edit out-link` 被拦（`[PERMISSION_REQUIRED]`，链接保持）；
  L4 自动放行 → 链接被替换、外部目标未改。
- 授权解析：`permission::resolve_target_path`（`permission.rs:345`）会 canonicalize 到目标；
  执行层用 `resolve_workspace_path`（`lib.rs:436`，只做词法归一）→ 两者对象不一致。

### 4. Level 2+ Read 无条件放行（BUG-04）

```text
L3 read outside symlink → success content="L1: secret"
L3 read /etc/hostname   → success content="L1: archlinux"
```

- `permission.rs:613`：`if category == ToolCategory::Read { return AutoApprove; }`，
  不检查 `classify_risk` 已算出的 outside（`permission.rs:73-79`）。

### 5. Windows 保留设备名（BUG-05，待本地验证）

- `resolve_workspace_path("NUL")` → `C:\ws\NUL`，词法上在工作区内；
  `resolve_target_path` 对设备名 canonicalize 失败时回落 → `all_within_workspace` 可能为 true
  → L3 写自动批准。
- `read_to_string("C:\ws\NUL")` → NUL 设备，空内容；`CON`/`COM1` 可能阻塞；
  `\\.\PhysicalDrive0` 等设备路径无显式拒绝。

### 6. 账本键分裂（BUG-06）

- `file_state::state_key`（`file_state.rs:118`）对存在的路径 canonicalize。
- read 链接 → 键 = 目标；write/edit 替换链接后 → 键 = 链接路径。
- 后果：read 基线/hash/偏移链与后续 edit 不在同一键上。

## 修复方向（建议，未实施）

### P0-1：read 类型守卫 + 有界读取（无策略争议，可直接做）

1. `read_one` 读前先 `std::fs::symlink_metadata` / `metadata`：仅允许
   `file_type().is_file()`；char/block/FIFO/socket/dir → 结构化错误
   （`NOT_A_FILE` / `UNSUPPORTED_FILE_TYPE`）。
2. 有界读取：按字节上限边读边计数（超过 `READ_MAX_CHARS` 直接停并标记 truncated），
   不再 `read_to_string` 全量；循环中检查 `ctx.cancel`。
3. Windows：拒绝保留设备名与 `\\.\`、`\\?\GLOBALROOT` 前缀（与 BUG-05 一起）。
4. 顺带修 BUG-07（空文件返回空 body 或 `(empty file)`）。

### P0-2：符号链接写入策略（**需要拍板**）

- **方案 A（拒绝）**：最终组件是符号链接 → 报错 `SYMLINK_TARGET`，附解析后的目标路径，
  要求模型改用真实路径或显式确认。简单、无惊喜；会打断依赖链接的配置工作流。
- **方案 B（穿透，推荐）**：`write`/`edit` 写前 `canonicalize` 最终路径，`atomic_write`
  作用在**目标**上（链接保留）；授权、账本键、shifts 全部锚定 resolved path。
  与 `apply_patch`/`journal` 现有行为一致，符合 Unix 编辑器直觉；需要处理 dangling link
  （目标不存在 → 报错）与"链接在授权后被替换"的 TOCTOU（写前重新 canonicalize + 校验）。
- 无论 A/B，`apply_patch`/`journal`/`copy_range` 必须与 `write`/`edit` 统一。

### P1

5. BUG-04：Level 2/3 的 Read 对工作区外路径走审批（至少使用 `classify_risk` 的 outside）。
6. BUG-05：Windows 设备名/设备路径拒绝 + 本地 Windows 测试。
7. BUG-06：账本键统一到 resolved path；链接被替换时清理旧键。

## 修复记录（2026-09-19，工作区待提交）

策略定案：**符号链接写 = 拒绝并报错**；**L2/L3 工作区外读 = 需要审批**。

改动：

- `file_shared.rs`：新增 `PathGuardError`、`ensure_readable_regular_file`、
  `ensure_writable_regular_target`、`is_windows_reserved_name`、`reject_device_path`；
  新增 `READ_MAX_BYTES = 8 MiB`。
- `file_query.rs`：read 前置类型守卫 + 大小上限（FIFO/设备/大文件在打开前拒绝）。
- `file_mutate.rs` / `edit/handler.rs`：写前 `ensure_writable_regular_target`。
- `apply_patch_engine/mod.rs`：`resolve_workspace_path` 在 canonicalize **之前**检查
  最终组件 symlink（canonicalize 会把链接解析成目标），新增 `EngineError::SymlinkTarget`。
- `copy_range.rs` / `journal.rs`：写前接入同一守卫。
- `permission.rs`：Read 仅在 `all_within_workspace` 时 AutoApprove；工作区外读
  在 L2/L3 返回 AskUser（L4 仍 bypass）。

实测（外部探针经 `execute_with_context`）：

```text
read /dev/null      → UNSUPPORTED_FILE_TYPE（不再是 "L1: "）
edit /dev/null      → UNSUPPORTED_FILE_TYPE
read fifo           → 立即拒绝（timeout 5 不再触发）
read /dev/zero      → 立即拒绝（无 OOM）
edit/write link     → SYMLINK_TARGET；链接保持 symlink，目标不变
apply_patch link    → SYMLINK_TARGET；链接与目标都不变
L3 read /etc/hostname / out-link → PERMISSION_REQUIRED
L3 edit in-link     → SYMLINK_TARGET
L3 edit out-link    → PERMISSION_REQUIRED
```
