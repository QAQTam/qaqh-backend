# buglist（2026-09-17）— 子代理取消后「复活」：取消不传播 + 注入无视取消态

> 登记规则：一行一个缺陷；**详情进 `docs/report/`**，本文件只做索引与状态跟踪。
> 状态口径：`open` / `fixed（工作区，待提交）` / `fixed @{commit}` / `verified` / `wontfix`。
>
> 详情报告：[`docs/report/2026-09-17-子代理取消后复活根因-report.md`](../report/2026-09-17-子代理取消后复活根因-report.md)
> （含 daemon 实机日志铁证）。
> 发现来源：机主报告「已经在前端和后端都被判定 cancel 的 subagent 是怎么复活的？」。
>
> **共同根因**：取消只终止「子回合本身」，**不终止「子代理结果回灌父会话」这条边**；
> 而注入路径会主动 `clear_cancel()` 并开启新回合。三个缺陷叠加产生「复活」观感。

## 缺陷

| ID | 状态 | 项 |
|---|---|---|
| BUG-2026-09-17-01 | `open`（**P0**） | `spawn_subagent_inprocess` 不注册 liveness（`live_workers` 缺子 seed），使 `seal_orphan_channel_state` 的 liveness 门形同虚设。子代理**启动的同一秒**只要被请求一次 timeline 就被判孤儿封掉（日志 `sealing orphan active turn t1 for 46f4be22`），产生假 `cancelled=true` 终态 |
| BUG-2026-09-17-02 | `open`（**P0**） | `collect_subagent_result` 在 `did_cancel=true` 时**仍向父会话注入完整结果**（`qaqh-subagent/src/lib.rs:533-595` 注入块无 `did_cancel` 守卫）。`did_cancel` 只影响 `state_tag` 文案。日志铁证：`conversation cancelled` 紧接着 `inject accepted` |
| BUG-2026-09-17-03 | `open`（**P1**） | 系统注入路径（`as_system=true`）在 `LoopPhase::Idle` 时**无条件开新回合**（`loop_injection.rs:196-220`），且 `engine_input.rs:261-262` 主动 `clear_cancel()`。无「本会话是否已被用户取消」的检查 → 父会话被「复活」 |
| BUG-2026-09-17-04 | `open`（**P1**） | 父会话取消时**不传播到子 seed**。全仓搜 `children`/`descendants` 的 cancel 传播：零命中。父会话记录自身子 seed 集合的能力也不存在 |
| BUG-2026-09-17-05 | `open`（**P2**） | `ProcessRegistry::mark_exited`（`process_registry.rs:478`）**无条件覆盖**状态，会把已 `Killed` 的条目改回 `Exited`，违反 `is_running` 注释（L463-465）声称的「status 单调，一旦离开 Running 不会回退」 |
| BUG-2026-09-17-06 | `open`（**P2**） | TUI `apply_status` 收到 `CANCELLED` 后只改 `SubagentEntry.state`，**不停止该 seed 的 timeline 跟踪**（`subagent.rs:207-215`）。导致已终态 seed 被周期性 `GET .../timeline -> 401`（日志 L5882/5893/5913）。`mark_subagent_closed` 只在 404 路径被调用 |
| BUG-2026-09-17-07 | `open`（**P2**） | `hub.mark_worker_dead` **全仓只定义、从未被调用**（`grep -rn mark_worker_dead crates/` 仅命中定义处）。`live_workers` 只靠 `hub.forget_seed`（`hub.rs:791-793`）在会话关闭时清理 → 子代理正常退出后仍滞留在活表中，直到 `forget_seed` 被调 |

## 修复优先级

1. **BUG-01**（1 行）：`spawn_subagent_inprocess` 补 `mark_worker_live` + 退出路径补 `mark_worker_dead`。
2. **BUG-02**（1 个守卫）：注入块加 `&& !did_cancel`。
3. **BUG-03**：系统注入路径区分「用户取消」与「回合取消」语义。
4. **BUG-04**：父会话登记子 seed 集合并传播 cancel。
5. **BUG-05/06/07**：状态单调性守卫 + TUI 停止跟踪 + `mark_worker_dead` 接入退出路径。

## 验证方式（修复后）

1. 子代理 spawn 后应见 `worker alive for {seed}; skipping bootstrap orphan seal`，而非 `sealing orphan active turn`。
2. cancel 路径下**不再出现** `inject accepted`。
3. 取消后父会话**不再出现**新的 `TurnStart`。
4. 已终态 seed 不再被周期性 `GET .../timeline`。
