## 2. 已冻结的架构裁决（不要重新开题）

以下方向已跨 backend、TUI、Codex、Grok 三方交叉，后续修复只允许做一致性收口：

1. 每 session 一条 append-only canonical `events.jsonl`；其他 journal/snapshot/offload 只能是派生缓存。
2. `SessionActor` 是 session 状态唯一 owner；外部只提交 command。
3. `TurnCore` 是纯状态机，不 await、不碰文件/网络/线程/锁。
4. `ToolRuntime` 统一 admit、schedule、sandbox、cancel、audit；loop 不内联工具执行细节。
5. `SessionFact -> ProjectionEvent -> WireEvent` 分层；canonical cursor 为 `(log_id, fact_seq, projection_index)`。
6. 工具默认 at-most-once + reconciliation；`ToolFinished::Indeterminate` 是不可逆终态。
7. `AuditStore` 是独立全局 hash chain，不进入 session projection。
8. v2.0 保留 daemon/TUI 两进程；embedded 单 binary 延后到 v2.1。
9. canonical fact 同版本未知 kind/payload version fail-closed；additive/`Unknown` 只覆盖 wire/display/resource/service。
10. 子代理先做 parent/child edge、supervisor、mailbox、quota；graph scorer/role template 延后。

## 3. 当前开放阻断（D1-D7）

本节是 **唯一开放阻断清单**。plan 只引用本节，不重复维护字段级状态；spec 是字段与状态机的唯一细节来源。

### D1 — commit/clock 第三态必须进入 spec

**状态：已收口，待复审**

- `RecoveryOutcome` 必须包含 `CommitRecoveryRequired`。
- commit marker 更新失败、EIO、marker 缺失/损坏但无法安全重建时，必须进入该状态，不得复用 `ReadOnlyUpgradeRequired`。
- 顺序固定为：fact fsync -> commit marker durable -> clock/replay window 推进 -> publish/ack。
- spec 的启动流程、§5.2 规则 7/8、§6.2、poison fixture 必须同步。
- fixture 至少覆盖：marker write failure、fsync EIO、crash-before-rename。

**Owner**：Codex / schema-recovery
**Gate**：三组 fixture 只有一个恢复解释；clock 不越过 committed high-water。

### D2 — trigger-turn 判别字段必须唯一

**状态：已收口，待复审**

- `InputAccepted` 必须有显式 `input_purpose: trigger_turn | queue_only`。
- `RecoveryStep::TurnStarted` 只允许匹配 `input_purpose=trigger_turn`。
- queue-only 只持久化/投递，不得补 turn。
- 全文删除或降级旧的 `input_kind=system + actor=subagent` 判别口径。
- fixture 必须包含正向 trigger-turn 与反向 queue-only。

**Owner**：Codex / schema-recovery
**Gate**：同一 `input_id` 最多一个 `TurnStarted`；queue-only 在重复 load 下仍无 turn。

### D3 — child terminal digest 必须与 completion 同集合

**状态：已收口，待复审**

- `child_terminal_digest` 至少覆盖 `child_session_id`、`child_log_id`、`terminal_fact_seq`、`terminal_event_id`、`status`、`parent_call_id`、`result_ref`、`finished_at_ms`。
- 该集合必须与 `RecoverySubagentCompletion` 一一对应；新增 completion 字段时同步 digest。

**Owner**：Codex / schema-recovery
**Gate**：同 batch key 不可能对应不同 `plan_hash`。

### D4 — quota ledger 必须是 root 级共享账本

**状态：已收口，待复审**

- 路径固定为 `{data_dir}/quota/{root_session_id}/ledger.jsonl`，并显式列出 `quota.lock`。
- owner 为 root `SessionActor` / `SubagentSupervisor`；root 与全部 child 经同一 lock 串行 append。
- child close/delete/cutover 不得删除账本；仅 root 生命周期结束且保留期过后按显式 GC 清理。

**Owner**：Codex / schema-docs
**Gate**：多 child reservation 无超卖；账本不随 child 生命周期消失。

### D5 — 特殊 recovery batch 必须分类可机械核对

**状态：已收口，待复审**

- 普通 recovery、unknown fact、upgrade supersede、commit/poison repair、tombstone 必须分别定义 fact/side effect 集合、幂等键与可写性。
- `upgrade_superseded`、`commit_repaired` 是显式 no-step sidecar action，不进入 `RecoveryPlan.steps` / `plan_hash`。
- `RecoveryAction` 与 `RecoveryStep` 的映射必须有唯一表或规范句。
- poison fixture 的期望状态必须是 `commit_recovery_required`，不得写“只读”。

**Owner**：Codex / schema-recovery
**Gate**：step/action/幂等键三张表可机械核对；不存在无法归类 batch。

### D6 — `SubagentSpawned.recovery_ref` 必须是 phantom-free

**状态：已收口，待复审**

- `recovery_ref` 只属于 `SubagentFinished`。
- `SubagentSpawned` 只能由正常两阶段 spawn 写入；recovery 不得伪造或重写 spawn edge。
- plan 必须拆成两行，spec §7.3 必须明确该不变量。

**Owner**：Codex / schema-docs
**Gate**：跨文档检索不存在 `SubagentSpawned` + `recovery_ref` 的组合。

### D7 — head、状态和清单必须单一来源

**状态：已收口，待复审**

- handoff 不固化 SHA；一律以 PR 当前 head 为唯一来源。
- plan 不再复制 head 或 D1-D7 清单，只引用本 handoff。
- PR 状态统一为 `open / mergeable / changes_requested`，直到 NPC 改为 approved。
- `I1..I18`、sidecar 检索和 fixture 清单必须与本 handoff/spec 一致。

**Owner**：Codex / docs-index
**Gate**：全仓只存在一份开放阻断清单、一个 head 事实来源；NPC 明确确认 D1-D7 闭环。
