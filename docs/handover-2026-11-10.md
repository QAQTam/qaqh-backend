## 3. 硬不变量（违反就是 bug）

1. **`main ⊇ LTS-v3.0`**。判据只能是 `git merge-base --is-ancestor origin/LTS-v3.0 HEAD; $LASTEXITCODE`
   （**0=成立**；`if (git …)` 判的是输出是否为空，该命令不打印任何东西 → 永远走 else）。
   ⚠️ 这条**至今没有机器闸**（只在规则 19/本文里），本轮已两次被并发写入者撞破。
2. **金标准与快照只能机器写**：`export --out` / `--rebaseline` / `--pin-frozen`。手改 = 判红（ADR-0011）。
3. **改冻结面前先读 ADR + 打三分类标记**；标记真假由 `check-surface-change-policy.py` 自己算。
4. **新增/退役闸门必须进 `docs/adr/`**，且引用时看状态字段（`提议中` ≠ 已实施）。

## 4. 下一步待办（按依赖排序，锚点与分母都是本轮实测）

### P0 出站/幂等面的同类残点（**不动契约产物**，最快见效）
`json_response` 已收口，但这 5 处**绕过它**自己拼响应，仍是 `to_vec(...).unwrap_or_default()` ⇒ 编码失败发**空体**：
- `crates/qaqh-daemon/src/axum_server/axum_impl/service_api.rs:44, 88, 96, 102`
- `crates/qaqh-daemon/src/axum_server/axum_impl/content.rs:277`
改法：走 `json_response`，或在本函数内显式 500（别加兜底）。
待判定（**不是**结论）：`v2.rs:810-811` 游标 `parse::<u64>().ok()`（SSE 规范允许忽略未知 `Last-Event-ID`，
但"垃圾游标"与"无游标"现在同形）；`content.rs:221-222` `String::from_utf8(...).ok()`（非 UTF-8 的
`session_id`/`media_type` part 静默缺席）。`from_*().ok()` 这一类在 daemon/ringing/client/runtime 已**归零**。

### P1 IR 扩面（ADR-0008 第 1 步的剩余；决定"新线 C# 有没有精度损失"能不能被验证）
- 分母实测：`cfg_attr(feature = "ts", derive(TS))` **263 处**；`feature = "schema"` 只有 **8 处**
  （`qaqh-memwatch` 7 + `qaqh-ringing-contract` 1）⇒ `ir-diff` 覆盖率 **8/236 = 3.4%**。
- 需要新加 `schema` feature 的 crate（已有 `ts` 但无 `schema`）：`qaqh-types`、`qaqh-ringing`、
  `qaqh-ringing-runtime`、`qaqh-runtime`、`qaqh-config-api`、`qaqh-siwc`、`qaqh-dsaccount`、`qaqh-profile`。
  现成模板：`qaqh-memwatch`（`schema = ["dep:schemars"]` + `#[cfg_attr(feature = "schema", derive(schemars::JsonSchema))]`）。
- 加完一型就把它塞进 `schema_backend::surface()`（**唯一清单**），`ir-diff` 立刻给出该型的属性级对账。
- 每步都可字节回查：`ir-diff` 不落文件；`export` 的 `contract_hash` 必须仍是 `39256ad9…`，否则就是顺手改了产物。
- 顺序结论（本轮改）：**扩面 > 替换**。`schema/` 折进 `generate()` 与 `GENERATOR_VERSION 0.2.0→0.3.0`
  留给删 `lex`/`parse_decl` 那一步（那一步重写 240 个 C# 文件头注释）。

### P2 ADR-0005 N-1 配对测试（切线文书的硬前置）

- 新测试名字必须含 `v2_`，否则 `sdk-contract.yml:39` 的过滤器会漏掉它（本轮就是这么办的）。
- 手上正好有一对真样本：v3.0 金标准（598 产物）vs main 的 601 —— 纯增量，正是配对测试该钉的形状。

## 6. 本轮新增的坑（别再踩）

1. **`continue-on-error` 会把 step conclusion 也写成 `success`** ⇒ 验收以 `--log` 为准（已修正手册 §1、ADR-0011、本文 §5）。
2. **"诊断-only"的改动也会改产物字节**：把 schema 文档统一走 `serde_json::Value` 往返再打印 ⇒
   键被 `BTreeMap` 排序，预览树 9 个文件全变。拆成 `published`（`to_string_pretty(&RootSchema)`）
   与 `facts`（`Value`）两条通道，并拿旧树逐 SHA256 回查。
3. **别凭记忆写库的行为**：`serde_json` 对 `NaN/∞` 在 `to_value` 和 `to_string` **两条路都写 `null`**，
   只有浮点当 **map 键**才报 `float_key_must_be_finite`。我记反了一次 ⇒ CI FAILED 2 tests。
   花 20 秒跑探针（临时 `#[test]` + `println!`，跑完还原）比读源码记忆便宜。
4. **报错信息本身可以是误导源**：`compare_trees` 原来 dump 全部路径 ⇒ 一条 24KB 日志把要看的那 3 条埋了；
   改成都只报增删/差异清单 + `+N more`。
5. **PowerShell 与 CJK 的三类噪音**：`git rev-parse --short A B` 两参会 `fatal: Needed a single revision`（分两次调）；
   控制台会把 cargo/gh 的 UTF-8 输出显示成乱码（先 `[Console]::OutputEncoding=UTF8`，或直接读文件）；
   `rg` 不在 PATH（用 `Select-String` / `grep` 工具）。
6. 分类闸**看不见"改了契约但没动金标准"的提交**（它的判据是改动落点）。所以 §1 那条 report-only 红是
   唯一的漂移信号，而 ADR-0011 的锁身份是唯一的硬闸 —— 两者都在 `surface-policy.yml` 里，别关掉。

沿用上一轮的 6 条（都还在咬人）：

7. **EOL**：`core.autocrlf=true` + `* text=auto` ⇒ 金标准在 Windows checkout 曾是 CRLF，导出物是 LF，
   守卫用 `read_bytes()` 就 599 文件整树假红。`.gitattributes` 已钉 `docs/api-surface/** text eol=lf`，
   但**改属性不会重写工作区**：得删文件再 `git checkout -- <path>`（`git checkout-index -f` 实测无效）。
8. `compare_snapshot` 用 `read_text()`（universal newlines）从来不受 EOL 影响；受影响的只有
   `compare_file_set`。写结论前先用探针分清范围 —— 我曾把它夸大成"整个守卫不可用"被打脸。
9. `.gitattributes` 里的 **merge 冲突标记会被 git 当属性行解析**（`>>>>>>> origin/LTS-v3.0` →
   `not a valid attribute name`）。这类文件冲突要手工修，别信自动合并。
10. `gh label create` 的 description **≤100 字符**，且 CJK 在 PowerShell 管道里有被写坏的风险 → 用 ASCII。
11. lint 报行号时必须**保号**去注释（置空而非删行），否则报错位置偏 30 行，闸门自己变成误导源。
12. 逐文件 `git show` 做 diff 会 spawn 上千次进程（50s）；先用一次 `--name-status` 拿增删改。
13. **别把"看起来成立"的结论直接写进文档**：本轮同一毛病第 3 次（"先切 v3.1 会冻住 possibly-wrong 的 C#"
    被 `ir-diff` 收窄成"冻住精度无人看守"；PowerShell 数 `double` 得 1、实际 2；`to_vec(NaN)` 记成会报错）。
    先跑反证/探针再落笔，尤其当你打算夸大成"整个 X 不可用"或"一定会报错"。
