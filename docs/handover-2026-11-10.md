## 6. 本轮踩过的坑（别再踩）

1. **EOL**：`core.autocrlf=true` + `* text=auto` ⇒ 金标准在 Windows checkout 是 CRLF，导出物是 LF，
   而守卫用 `read_bytes()` → 599 文件整树假红。修法已进 `.gitattributes`（`docs/api-surface/** text eol=lf`），
   但**改属性不会重写工作区**：得删文件再 `git checkout -- <path>`（`git checkout-index -f` 实测无效）。
2. `check-lts-api-surface.py` 的 `compare_snapshot` 用 `read_text()` → universal newlines，**从来不受 EOL 影响**；
   受影响的只有 `compare_file_set`。写 ADR 时我一度夸大成"整个守卫不可用"，被自己探针打脸后收窄。
3. **`.gitattributes` 里的 merge 冲突标记会被 git 当属性行解析**（`>>>>>>> origin/LTS-v3.0` →
   `not a valid attribute name`）。这类文件冲突要手工修，别信自动合并。
4. `gh label create` 的 description **≤100 字符**，且 CJK 在 PowerShell 管道里有被写坏的风险 → 用 ASCII。
5. **CI 的 job success 会掩盖步骤失败**（`continue-on-error`）：验收新闸门必须看
   `gh run view <id> --json jobs --jq '.jobs[0].steps'` 的明细。
6. lint 报行号时必须**保号**去注释（置空而非删行），否则报错位置偏 30 行，闸门自己变成误导源。
7. 逐文件 `git show` 做 diff 会 spawn 上千次进程（50s）；先用一次 `--name-status` 拿增删改。
8. 我两次把"看起来成立"的结论写进文档后才发现反例（ADR-0003 初版误判"没有 registry"；
   两分类被 doc-only 案例证伪）。**先跑反证再落笔**，尤其当你打算夸大成"整个 X 不可用"。
