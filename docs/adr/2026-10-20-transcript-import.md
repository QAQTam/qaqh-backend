# ADR：导入专用 crate 与可追溯会话归档

日期：2026-10-20。状态：独立核心已实现；本轮 review 后确定以下兼容与协议策略，集成未实施。

## 背景与授权

用户明确要求设计导入专用 crate，分三阶段：Claude Code 消息无损导入、Codex、其他来源。
当前 qaqh 消息类型可以表达常用内容，但缺少完整来源、分支、原始字节和未知记录的持久契约。
当前消息归档和 canonical 读取链路尚未完全收敛，本功能不能扩大独立消息权威写入。

## 决策

1. 新增 `qaqh-import` 作为来源格式的所有者，负责发现、快照、解析、规范化和校验。
   crate 不创建正式会话、不管理 actor、不执行历史工具，也不依赖 provider SDK。
2. 原始字节和规范化消息图同时保留，覆盖检查与完整性报告是导入结果的一部分。
   保存原始文件不等于完成消息语义转换；未知/损坏内容不能静默丢弃。
3. 跨边界持久契约归 qaqh-types，提交、blob 与投影归 session；宿主负责编排。
4. 提议新增来源无关的 `TranscriptImported` canonical fact 引用包清单；原始及规范化正文全部入 blob。
   不伪造在线回合/工具意图，不通过普通元数据字段夹带新业务事实。
5. 第一阶段导入全部分支与子代理记录，提供只读查看和原始取回；继续对话单独验收。
6. 不新增 messages.jsonl 长期双写；正式读取不回退到 Claude 文件或执行 migrate-on-read。

## 协议影响与实施边界

本轮用户要求 review 并确定策略，结论采用 [兼容与 IMP-06 协议](../spec-transcript-import-protocol.md)：

- 只读导入归档存入独立 `archives/`，普通 sessions 列表/恢复入口不包含它。
- 新增磁盘 fact `TranscriptImported`；旧客户端不接收该事实或新投影枚举。
- Ringing 保持 v2，open capabilities 加默认 false 的 transcript_import。
- 导入与查询方法使用现有 service 路由，新增一个按 artifact ID 取回原始字节的流式 GET。
- 协议文档固定方法、回包、错误、幂等、取消和发布顺序，作为本 ADR 的局部 wire 扩展范围。
- context unknown 仍可发布消息完整的只读归档；partial 需显式 allow_partial，损坏包始终拒绝。
- 正式开放能力前必须修复 review 阻塞项并完成新旧客户端矩阵，不表示已有客户端天然兼容。

此前“入口和兼容策略待定”的实施前置条件由本次决策替代；新增功能尚未接通。

新 crate 的独立边界是实际外部格式适配需求；现有 config 的 MCP 配置导入不迁移。
没有待删除的旧会话导入器；不将新增功能伪装成 CLEAN 净删工作。

## 后果

导入包能在源目录删除后继续读取和取回；新的来源复用包与提交能力。
代价是 blob 存储量增加、需要来源图契约和独立导入展示投影；规范化契约应有版本和升级策略。
任何缺失附件、未知语义、来源变化或提交失败均有明确状态，不能返回无条件成功。

详细格式、API、事务、测试与三阶段任务见 [导入设计](../spec-transcript-import.md)。
