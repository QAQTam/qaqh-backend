## 0. 结论先行

### 0.1 一句话架构

> **每个 session 只有一条 append-only canonical fact log；每个 session 只有一个状态所有者；所有历史、timeline、control、resource、service 与 UI 视图都是该日志的可重建投影；工具只在 ToolRuntime 中执行，并以 typed outcome 返回；客户端只消费版本化 wire 投影，不读取存储布局。**

目标形态：

```text
                       ┌──────────────────────── clients ────────────────────────┐
                       │ TUI / Web / WinUI / CLI / headless                     │
                       └───────────────────────┬─────────────────────────────────┘
                                               │ Ringing wire / typed client API
                       ┌───────────────────────▼─────────────────────────────────┐
                       │ Node transport: HTTP+SSE / UDS / stdio                 │
                       │ connection registry · subscription · auth · request id │
                       └───────────────────────┬─────────────────────────────────┘
                                               │ SessionCommand / ProjectionEvent
┌──────────────────────────────────────────────▼────────────────────────────────┐
│ SessionActor (unique owner per session)                                       │
│                                                                               │
│  SessionState ── TurnCore(step) ── TurnDirective                              │
│       │                │                                                      │
│       │                ├── GateHost ── LLM gateway                            │
│       │                ├── ToolRuntime ── Policy/Sandbox ── Tool implementations│
│       │                └── Compaction/Title/Subagent task ports               │
│       │                                                                       │
│       ├── SessionStore: append SessionFact; fsync barrier                     │
│       ├── ProjectionSet: conversation/timeline/control/resources              │
│       └── InteractionRegistry: permission/ask/plan, first-answer-wins          │
└───────────────────────────────┬───────────────────────────────────────────────┘
                                │ facts -> derived views
                 ┌──────────────▼──────────────┐
                 │ canonical files             │
                 │ events.jsonl                │
                 │ content/<hash>              │
                 │ derived/ snapshots          │
                 │ audit/ (separate ledger)    │
                 └─────────────────────────────┘
```

### 0.2 五条不可妥协的不变量

1. **单一事实源**：`events.jsonl` 是 session 历史唯一 canonical source；`messages.jsonl`、timeline 快照、journal、checkpoint、offload、dashboard、todo 文件都不能反向成为恢复所需的事实源。
2. **单一状态所有者**：每个 session 的 TurnState、投影、订阅、pending interaction 和取消状态只由 `SessionActor` 串行修改；外部模块只能发送 command / 接收 event。
3. **先提交后发布**：任何会影响恢复的 fact 必须先 durable append，并由 `events.commit.json` 固化 committed high-water，之后才能推进 clock/replay window、更新投影和发布/ack；派生 projection 可以滞后，但绝不能领先 canonical log。
4. **工具调用有终态且至多一次副作用**：执行前写 `ToolIntent`，执行后写唯一 `ToolFinished`；`Indeterminate` 是不可逆终态，崩溃恢复不得自动重跑非幂等工具，也不得接受同一 call 的再次 resume。
5. **投影分层**：`SessionFact`（持久事实）、`ProjectionEvent`（服务端投影）、`WireEvent`（协议事件）是三种类型，不再用同一个 `RingingEventEnvelope` 同时承担存储、游标和 UI 语义。

### 0.3 三方交叉裁决

| 决策 | Codex | Grok | QAQH v2 裁决 |
|---|---|---|---|
| 事实源 | rollout JSONL + SQLite 显式 metadata/查询投影 | `updates.jsonl` 事实源 + `chat_history` 派生缓存 | **单 session JSONL fact log + 可重建投影；metadata mutation 必须进显式 fact；SQLite 非 v2.0 必需** |
| 进程模型 | 单 binary，embedded/local daemon/remote 三态，共用 app-server 语义 | 单 binary composition root，embedded/leader/stdio/headless | **v2.0 保留 daemon/TUI 两进程，但先统一语义边界；embedded composition root 列为 v2.1 候选** |
| 状态所有权 | thread listener actor + session task + token tree | SessionActor + ChatStateActor + turn epoch | **SessionActor 唯一 owner；TurnCore 纯状态机；不拆第二套 chat-state actor** |
| 重连 | 历史投影 + 原子订阅；只重放阻塞请求 | `session/load` 流式重放 + event_seq 去重 | **snapshot baseline + `since_cursor` reliable replay + atomic subscribe；replaceable 不承诺逐条回放** |
| 工具 | 执行、approval、sandbox、output 多投影分层 | typed ToolOutput + permission/pending interaction | **ToolRuntime 统一 admit/schedule/execute/audit；loop 不碰执行细节** |
| exactly-once | 不是端到端执行保证；`SeenIds` 不能当 ledger | attempt store 设计未接线 | **必须新增 durable intent/result ledger；不能把 call_id 当幂等** |
| 多客户端 | connection/thread 双向订阅，listener generation | driver + subscriber + first-answer-wins | **subscription 与 driver 分离；driver 是显式能力租约，不是“第一个连接者”** |
| 权限 | execpolicy + approval + OS sandbox + escalation | rules + permission mode + nono + Auto classifier | **OS sandbox 是地基；规则引擎输出 allow/deny/ask/amend；四级档位仅作 preset** |
| 子代理 | graph + roles + mailbox + persisted edges | child runtime + message delivery/Principal | **先做 parent/child identity、queue-only/trigger-turn、持久 edge；不引入 graph scorer/role 模板** |
| 测试 | nextest + 行为 suite + fixture/故障注入 | mock inference + PTY + UDS fault proxy | **三层：纯状态机、wire/replay transcript、真实 daemon/IPC/PTY e2e** |

## 1. 当前事实基线与根因

### 1.1 backend 现状

- daemon 是单进程入口；session/subagent actor 在 daemon 内以 OS thread 运行，不是 child process：`crates/qaqh-runtime/src/registry.rs`、`crates/qaqh-runtime/src/actor.rs`。
- TurnEngine/ToolEngine 同时承担 gate、权限准入、工具线程、进度泵、timeline 发射、outbox、终态和 compaction：`crates/qaqh-runtime/src/agent/engine_turn.rs`、`engine_tool.rs`、`turn_lap/admit.rs`。
- Ringing 仍有三频道物理 journal、`latest/` checkpoint、timeline 快照、offload 侧车；session 另有 `messages.jsonl + WAL + meta/index`：`crates/qaqh-runtime/src/ringing/journal_store.rs`、`timeline_store.rs`、`crates/qaqh-message/src/wal.rs`、`crates/qaqh-session/src/manager.rs`。
- Tool SDK 已有 `ToolProjection`、`ToolOutcome`、`ExecuteBatch`、`ToolCapabilities`、`LegacyToolAdapter` 骨架，但生产路径仍使用 `ToolHandler` + `serial_call_ids` 手工编排，未接线：`crates/qaqh-workspace/src/tool_api/`、`tool_capabilities.rs`。
- Workspace v2、Ringing v2、审计 v2、展示 v1 的文档状态和实现状态不一致；部分类型只有草案或骨架，没有生产调用点。
- v2 前瞻计划本身已指出根因：**同一事实至少存在 6-7 份，且 loop 内联了四层职责**。

### 1.2 TUI 现状

- TUI 已通过 `qaqh-client` 统一传输，不再手抄大部分协议类型：`qaqh-tui-app/src/protocol/mod.rs`。
- 但 session 状态仍由 bootstrap、三频道 SSE、timeline stream、service `Value` 四路合流；attach、bootstrap、timeline activate 存在双所有权：`src/app/session_ops.rs`、`src/runtime.rs`。
- service response 仍是 `Value`，dashboard/todo 手解；timeline rebaseline 缺少 epoch/watermark/seq 防护。
- 渲染管线 M1/M2/M3 的主体已落地：block-level cache、ToolView 主体、progress 字段消费和跨仓 fixture 已在 TUI 文档标记完成；剩余真实缺口是 dirty/throttle 全覆盖、旧 H16 豁免、interaction 幂等、reconnect/rebaseline 和单 SessionModel 收口。

### 1.3 参考实现的共同结论

Codex：

- app-server 语义独立于进程边界；embedded/remote 只换 transport，不换 session/approval 契约。
- canonical history append-only；同一 thread 单一 live writer。SQLite 既承载可重建 history projection，也承载显式 metadata mutation，不能把其中所有内容都当成可随手丢弃的缓存。
- thread listener 用 command queue 串行化“历史投影 + 原子订阅”。
- turn/task、tool、approval、sandbox 是不同所有权域。
- `SeenIds` 不是 exactly-once；真正的执行去重必须另有 durable ledger。

Grok：

- `updates.jsonl` 是唯一事实源，`chat_history.jsonl` 是派生缓存。
- SessionActor 与 ChatStateActor 分离；turn 有 prompt/epoch 身份，finalization 过同一 gate。
- `session/load` 单播重放，live 广播；`event_seq` 去重。
- permission/ask/plan 是 pending interaction；driver 和 subscriber 分离。
- 不照搬 per-session OS thread、unbounded channel、隐式 driver 迁移和未接线的 attempt store。

### 1.4 根因判断

当前问题不是“Ringing 代码太多”或“TurnEngine 文件太大”本身，而是四个边界没有建立：

1. **持久事实与派生投影边界**缺失；
2. **session 状态与连接状态边界**缺失；
3. **turn 决策与 IO/工具执行边界**缺失；
4. **canonical output 与多消费者投影边界**缺失。

因此新架构必须优先修边界，而不是继续按文件拆小。

### 1.5 本机代码还原出的迁移边界

以下结论来自当前实现，不应被文档冻结误写成“已经具备”的能力：

| 当前代码事实 | 证据 | plan 的正确处理 |
|---|---|---|
| in-process child actor 由 registry 记录 parent/child edge，但 `close(parent)` 只移除实例并 `unlink_subagent(parent)`，不会取消/join 仍在册 child | `crates/qaqh-runtime/src/registry.rs` 的 `close`/`unlink_subagent` | `SubagentSupervisor`、canonical edge 与 cancel/join 是 P2 迁移目标，不是现状保证 |
| idle unload 明确排除非 `AgentKind::Session`；liveness 只表达 busy/suspend，不持有 child set | `registry.rs::unload_idle_sessions`、`crates/qaqh-runtime/src/agent/liveness.rs` | 父 session 的 unload 判据必须增加“直接 child set 为空”；child worker 不进入全局 idle 候选 |
| `ConversationCancel` 会传播给已登记 child，但 `close`、archive/delete 与 daemon shutdown 不走同一条传播路径 | `registry.rs::cancel_subagent_children`、`service.rs::close_session/delete_session`、`registry.rs::shutdown_all` | 四种入口必须统一到 supervisor；`SessionDeleted` 级联 tombstone，shutdown 先停 admission 再 join 全树 |
| `ToolStatus` 只有 `Ok/Error/Partial/Backgrounded/Cancelled`，没有 `Indeterminate`；pending permission 仍主要靠内存/旧快照恢复 | `crates/qaqh-types/src/tool_result.rs`、`crates/qaqh-domain/src/timeline.rs`、runtime resume 路径 | P3 增加 typed terminal；resume admission、terminal lookup 与 `ToolIntent` 必须在 actor 内原子完成 |
| audit v2 已有全局 hash chain/rotate/torn-tail，但 append 仍是 `write_all`，没有唯一 `AuditWriter` 或 durable ack | `crates/qaqh-workspace/src/audit/v2.rs` | P4 保持现有账本格式，补全局 writer ownership、`sync_data` barrier 与失败后的 `Indeterminate/quarantine` |
| 当前没有 canonical `events.jsonl` 的 commit/poison/upgrade sidecar，也没有 root 树 `QuotaLedger` 实现 | 本仓 `crates/**` 无对应生产类型/调用点 | P1/P2 才实现；P0 只冻结协议、owner、路径与故障语义 |

## 2. 版本与兼容政策裁决

### 2.1 三种版本必须分开命名

| 名称 | 含义 | 示例 |
|---|---|---|
| 产品版本 | QAQH 发布版本 | `v2.0` |
| Wire 版本 | HTTP/SSE/UDS 协议版本 | `Ringing v2` |
| 存储 schema | canonical fact / projection 格式 | `qaqh.session-fact/v2` |

禁止再把产品 `v2.0`、Ringing `v1`、Workspace `v2`、审计 `v2` 混称为同一个“v2”。

### 2.2 兼容矩阵

此前文档冲突的“完全不兼容”和“全部向前兼容”都不采用。按平面分别定义：

| 平面 | 兼容策略 | 理由 |
|---|---|---|
| Ringing core | 新协议 `Ringing v2` 并行端点；v1 提供一发布周期映射层 | 重连语义从 `Last-Event-ID` 到 `since_cursor`，不能假装无 breaking |
| 工具 display | additive + `Unknown` + 完整旧字段回退 | 前端必须跨 server 版本工作 |
| resource/state event | additive + revision 去重 + `Unknown` 保留 | todo/skills/plan 需要渐进迁移 |
| service response | 新 typed response；旧 `Value` 只作 legacy adapter | TUI 不能再手解 JSON |
| 存储 schema | 版本号 + 单向迁移；canonical fact 不做 additive 跨版本读取，旧二进制遇到未知 `kind`/`payload_version` 必须 fail-closed | 内部存储不承担跨版本双写长期成本；升级到支持新 schema 的二进制后可恢复读写 |
| 旧 ringing 目录 | 一次性迁移/清理命令；观测期后可删除 | journal/checkpoint 不是 wire 契约 |

### 2.3 兼容原则

1. wire 新增字段必须 `Option + serde(default)`，新增枚举变体必须能映射为 `Unknown`。
2. 客户端只忽略未知字段，不推测未知语义；需要新语义时必须升级协议能力位。
3. additive/`Unknown` 兼容只覆盖 wire、tool display、resource/state event 与 service response，不承诺 canonical fact 可被旧二进制解释。新增 canonical fact kind 或改变 payload 语义必须提升 `payload_version`。
4. canonical fact 对同一 schema 版本遇到未知 kind 或未知 payload version 必须 fail-closed：将 session 标记 read-only/upgrade-required，不得跳过未知 fact 继续解释后续事实；未知普通字段仍按 `serde(default)` 忽略。对未知 payload version，旧 writer 不得追加任何业务 fact，只允许按 schema spec 追加唯一的 `SessionRecovered { outcome=read_only_upgrade_required }` 恢复标记；该标记不宣称理解未知版本。
5. read-only 是安全状态而非永久锁：支持全部 payload version 的新 writer 必须先验证整条日志，再按 `upgrade-fence.json` 的单调 generation 写 `state=writable`，随后以新的 recovery identity 写 `SessionRecovered { outcome=writable, last_good_fact_seq=当前日志尾 }` 或等价的版本迁移 fact，之后才可恢复写入。旧 writer 看到更高 generation 的 writable fence 时不得追加 read-only marker 覆盖该决定。
6. 旧字段的保留期由兼容矩阵明确，不以“以后可能需要”为理由永久双写。

### 2.4 v1 重连映射与 cutover

| v1 | v2 | 规则 |
|---|---|---|
| `Last-Event-ID = epoch:channel:stream_seq` | `since_cursor = {log_id, fact_seq, projection_index}` | 用 `(epoch, channel, stream_seq)` 查兼容映射表；v1 SSE id 的第三段是全局 `stream_seq`，不是 per-seed `channel_seq` |
| 映射表值 | `{session_id/seed, fact_seq, projection_index, delivery}` | 命中事件若不属于当前订阅 session，必须走 `ResetRequired`，不能静默映射 |
| channel reliable replay | canonical reliable replay | 转成复合 cursor 后，按 `(fact_seq, projection_index)` 字典序回放 |
| replaceable checkpoint | 当前 projection value | 连接时发送一次 current value，不推进 cursor |
| snapshot baseline | `ResetRequired { log_id, snapshot_cursor }` | cursor 过期或 epoch 不匹配时强制重基线 |
| lease ownership | auth lease + driver capability | 鉴权续期不改 driver；driver 由能力租约单独移交 |

cutover 条件：

- 双写观测期内，canonical 投影与旧快照行为差异为 0；replay live 等价测试连续通过。
- `Last-Event-ID` 映射覆盖所有活跃 channel；过期映射必须走 reset，不得静默跳事件。
- rollback 只需切回旧读路径；旧 writer 在 cutover 前不能停止，且必须经过单 writer facade。
- 对账差异、seq gap、投影 rebuild 失败任一超阈值时，禁止继续删除旧目录。

## 3. 目标逻辑架构

### 3.1 六层

```text
1. Contract / domain
   SessionFact · Projection · Command · Tool API · Policy API

2. Session kernel
   SessionActor · TurnCore · InteractionRegistry · Cancellation tree

3. Execution
   GateHost · ToolRuntime · SandboxAdapter · Compaction/Title/Subagent ports

4. Persistence
   SessionStore · EventLog · ContentStore · ProjectionStore · AuditStore

5. Transport / projection
   RingingHub · SubscriptionRegistry · WireAdapter · ServiceAdapter

6. Clients
   qaqh-client · TUI · Web · WinUI · CLI/headless
```

### 3.2 依赖方向

```text
qaqh-types / qaqh-domain
        ▲
        │
qaqh-store ─ qaqh-turn ─ qaqh-tool-api ─ qaqh-policy
        ▲          ▲          ▲
        └──────── qaqh-runtime ────────┘
                     ▲
             qaqh-daemon / qaqh-client
                     ▲
                  clients
```

规则：

- `qaqh-turn` 不依赖 store、gate、workspace、transport；只依赖 contract。
- `qaqh-tool-api` 不依赖内置工具；`qaqh-workspace` 依赖它，而不是反向定义契约。
- `qaqh-policy` 不依赖具体工具实现；工具只声明 capability/risk。
- `qaqh-runtime` 是装配层，负责 actor 和跨域编排，不再承载协议存储细节。
- `qaqh-ringing` 只做 wire schema/adapter，不拥有 session 状态。

### 3.3 目标 crate 映射

不要求一次创建全部新 crate；先按 ownership 拆模块，稳定后再抽 crate。

| 目标 crate | 来源/动作 | 职责 |
|---|---|---|
| `qaqh-types` | 保留并瘦身 | 基础值类型、wire-compatible `ToolResult`、ID/时间/错误 |
| `qaqh-domain` | 保留并重整 | `SessionFact`、projection、command/event、资源 view |
| `qaqh-store` | 新抽 | append-only log、content store、projection materializer、writer lock |
| `qaqh-turn` | 新抽 | 纯 TurnCore 状态机、TurnInput/TurnDirective |
| `qaqh-tool-api` | 从 `qaqh-workspace::tool_api` 上提 | descriptor、capability、typed outcome、projection、ExecuteBatch |
| `qaqh-policy` | 从 `qaqh-workspace` 权限/沙箱抽出 | policy decision、rule、sandbox spec、approval grant |
| `qaqh-workspace` | 保留为 builtins | 19 个内置工具实现，依赖 tool-api/policy |
| `qaqh-runtime` | 保留但去内联 | SessionActor、ToolRuntime、GateHost、ProjectionSet、ResourceManager |
| `qaqh-ringing` | 保留为 wire | Ringing v2 envelope、channel 投影、v1 adapter |
| `qaqh-daemon` | 保留为入口/transport | HTTP/SSE、UDS、discovery、connection lifecycle |
| `qaqh-client` | 保留并 typed 化 | typed command/query、subscribe/reconnect、service response |
| `qaqh-tui` | 保留 | pure UI reducer + block renderer，不拥有 wire 语义 |

## 4. Canonical fact 与投影契约

### 4.1 三类事件必须分离

```rust
/// 1. 持久事实：唯一可恢复来源。
pub struct SessionFact {
    pub schema: FactSchema,
    pub session_id: SessionId,
    pub log_id: LogId,          // 重建/迁移/重置身份
    pub fact_seq: u64,          // per-session 单调递增，连续
    pub event_id: EventId,      // 幂等/因果追踪
    pub ts_ms: i64,
    pub causation_id: Option<EventId>,
    pub turn_id: Option<TurnId>,
    pub call_id: Option<ToolCallId>,
    pub interaction_id: Option<InteractionId>,
    pub payload: FactPayload,
}

/// 2. 服务端投影：由 fact/内存状态派生，可带 replaceable/transient。
pub enum Delivery {
    Reliable { cursor: ReliableCursor }, // 唯一可靠 cursor
    Replaceable { revision: u64 },       // 只给当前值
    Ephemeral,                           // 不回放、不推进 cursor
}

pub struct ReliableCursor {
    pub log_id: LogId,
    pub fact_seq: u64,
    pub projection_index: u16, // 同一 fact 内稳定且从 0 递增
}

pub struct ProjectionEvent {
    pub stream_key: StreamKey,
    pub delivery: Delivery,
    pub payload: ProjectionPayload,
}

/// 3. Wire 事件：协议版本与 client capability 适配后的结果。
pub struct WireEvent {
    pub wire_version: WireVersion,
    pub channel: RingingChannel,
    pub event_id: EventId,
    pub cursor: Option<WireCursor>, // 仅 Reliable 有 cursor
    pub payload: serde_json::Value, // 只在 adapter 边界存在
}
```

规则：

- `SessionFact` 不允许出现 UI 专属字段、动画状态或原始 SSE 文本。
- **canonical cursor 是 `(log_id, fact_seq, projection_index)`**；`fact_seq` 非递减，完整复合 cursor 严格递增。
- 一个 fact 可以产生 0..N 个 reliable `ProjectionEvent`；`projection_index` 在同一 fact 内稳定且从 0 递增。
- 订阅/replay 必须使用完整 `since_cursor = (log_id, fact_seq, projection_index)`；先要求 `log_id` 相同，再按 `(fact_seq, projection_index)` 字典序过滤。只传 `fact_seq` 不足以续传。
- `Replaceable` 只给当前值，`Ephemeral` 不回放；两者都不得推进 reliable cursor。
- `WireEvent` 是 adapter 输出，业务层不得读取 `serde_json::Value` 猜字段。
- `fact_seq` 只用于 canonical log；wire cursor 是其受控投影，不允许另造 per-channel authoritative seq。

支撑类型至少定义为：

pub enum SideEffectClass {
    ReadOnly,
    WorkspaceWrite,
    Process,
    Network,
    External,

pub struct WireCursor {

v2.0 至少定义以下事实：

说明：

- `TextDelta`、`ToolProgress`、动画帧不是 fact；它们是 `ProjectionEvent::Ephemeral`。
- `AssistantBlockSealed` 在块 seal 时写入；崩溃时未 seal 的流式文本不回放，由恢复流程将 turn 标记为 interrupted。
- `ToolIntent` 在执行前写入并 fsync；`ToolFinished` 是唯一终态。
- `WorkspaceResourceChanged` 由 `WorkspaceEffect` 提交产生，不允许工具直接写 control/timeline。
- `InteractionRequested/Resolved` 必须持久化，使 ask/plan/permission 在重连后可恢复。
- `SessionMetadataChanged` 必须显式承载 cwd/model/archive/search visibility 等用户或 API mutation；这些不是“可随手推断的索引字段”。
- `SessionRecovered`、`InteractionExpired`、`TurnInterrupted` 用于崩溃恢复后的闭合，恢复不得重写旧 fact。

| `ModelRoundStarted` | `turn_id, round, request_hash, context_revision` |

- `content_ref` 用于大内容；小字段可内联，但不得超过单 fact 上限。
- 字段删除/重命名必须通过新 fact kind 或版本迁移，不允许原地改变语义。

### 4.3 Projection 集合

每个 projection 必须实现：

```rust
pub trait Projection: Default + Send {
    type Snapshot: Serialize + DeserializeOwned;
    type Delta: Serialize + Send;
    fn apply(&mut self, fact: &SessionFact) -> Option<Self::Delta>;
    fn snapshot(&self) -> Self::Snapshot;
    fn last_fact_seq(&self) -> u64;
    fn rebuild(facts: impl Iterator<Item = SessionFact>) -> Self;
}
```

v2.0 的 projection：

| Projection | 消费者 | 是否可丢弃 | 关键身份 |
|---|---|---|---|
| ConversationProjection | model context、gate | 可重建 | turn/step/message |
| TimelineProjection | TUI/Web transcript | 可重建 | block_id/rev |
| ControlProjection | 状态栏、interaction | 可重建 | session revision |
| ResourceProjection | todo/skills/plan/activity | 可重建 | resource kind + revision |
| SessionMetaProjection | 列表/搜索 | 可重建，但依赖显式 `SessionMetadataChanged` fact | session_id |
| AuditStore | 合规查询 | **不属于 ProjectionSet，不从 session log 重建** | 全局 audit seq + hash chain |

`AuditStore` 是独立安全账本，继续使用 `{data_dir}/audit/v2.jsonl` 的全局 seq/hash chain；session 目录只允许保存可重建的审计索引或引用，不能把每个 session 的审计链拆断。进程内必须有唯一的 `AuditWriter` 所有权：所有 session actor 只能提交 audit intent/result，由该 writer 在单一临界区内分配全局 audit seq、追加并 fsync，返回 durable ack 后调用方才能继续。per-session writer lock 不保护 audit seq；audit intent barrier 失败时不得进入 handler，副作用后的 audit result barrier 失败时进入 quarantine/emergency sink，并把该 call 闭合为 `Indeterminate`，不得另起一条 audit chain。

### 4.4 文件布局

```text
{data_dir}/sessions/{session_id}/
  events.jsonl                 # canonical，单写者，append-only
  events.lock                  # OS 级互斥；不是 ownership 事实源
  writer-fence.json            # writer_id/generation_epoch/fencing_token CAS lease
  upgrade-fence.json           # 版本无关的 monotonic read-only/writable supersede 状态
  events.commit.json           # 最后一次 durable barrier 的 committed_fact_seq/offset
  events.poison.json           # fsync EIO 证据；不能替代 commit high-water
  content/{sha256}             # 大文本/图片/附件，内容寻址
  derived/
    conversation.json          # temp+rename，可重建
    timeline.json              # temp+rename，可重建
    control.json               # temp+rename，可重建
    resources.json             # temp+rename，可重建
    meta.json                  # 列表缓存，可重建
    audit_refs.json            # 仅指向全局 audit seq，不复制审计链

{data_dir}/quota/{root_session_id}/
  ledger.jsonl                 # root 树共享的 reservation/commit/release，append-only
  quota.lock                   # 独立于 events.lock 的跨 session 串行化/fencing 点

{data_dir}/audit/
  v2.jsonl                     # 独立安全账本，全局 seq/hash chain，不进模型面
  v2.jsonl.{1..N}              # rotate 代
  v2.jsonl.torn                # 撕裂证据
```

兼容期：

- 旧 `messages.jsonl`、`todo.json`、`ringing/{journal,latest,timeline,offload}` 只读或双写观测。
- 双写必须有 `canonical_seq` 对账，不得无限期保留。
- `timeline-audit` 是诊断日志，不是合规账本：一个兼容 milestone 内若无消费者则删除；若有消费者则改名 `diagnostics/timeline.jsonl`，并单独定义保留期。禁止与 `{data_dir}/audit/` 混用。
- `quota/{root_session_id}/` 不属于单个 session 目录，也不受 per-session `events.lock`/`writer-fence.json` 保护；child close/delete/cutover 不得删除它。只有 root 生命周期结束且保留期已过，才允许按显式 GC 规则清理。

### 4.5 内容引用与截断

- 单条 fact 内文本默认不超过 64 KiB；超出部分写 `content/<sha256>`，fact 保存 `ContentRef`。
- 所有 list/text 使用统一 `ListOutput<T>`、`BoundedText`、`TruncationMeta`。
- 模型投影、display、service、resource summary 都从同一 canonical output 派生。
- `output_bytes`（最终展示）、`progress_bytes_total`（累计观测）、`original_chars`（截断前）语义不得混用。

## 5. SessionActor 与 TurnCore

### 5.1 SessionActor 是唯一 owner

```rust
pub struct SessionActor {
    session_id: SessionId,
    state: SessionState,
    projections: ProjectionSet,
    interactions: InteractionRegistry,
    subscriber_ids: SubscriberRegistry, // 逻辑订阅关系；socket 归 transport
    driver: Option<DriverCapability>,   // 独立于鉴权 lease
    cancellation: CancellationToken,
}

/// 可序列化的客户端命令。
pub enum ClientCommand {
    Submit(InputEnvelope),
    ResolveInteraction(InteractionResolution),
    Cancel(CancelRequest),
    SetSubscription(SubscriptionRequest),
}

/// actor 内部命令，禁止进入 wire。
enum SessionActorCommand {
    Client(CommandEnvelope),
    Flush(oneshot::Sender<FlushResult>),
    Unload(UnloadReason),
    ConnectionClosed(ConnectionId),
}
```

所有客户端命令统一包裹为：

```rust
pub struct CommandEnvelope {
    pub command_id: CommandId,       // actor 幂等键
    pub client_id: ClientId,
    pub session_id: SessionId,
    pub expected_log_id: Option<LogId>,
    pub payload: ClientCommand,
}
```

不变量：

- actor mailbox 是 session 内所有状态变更的唯一入口。
- actor 按 `command_id` 去重；重复提交返回原 ack，不重复执行。
- `Flush/Unload/ConnectionClosed` 只存在于 `SessionActorCommand`，不得出现在 wire 类型。
- `SessionActor` 持有逻辑 subscriber 集合；transport 只持有 socket/connection，二者通过 `ConnectionId` 映射，禁止各维护一份 session 订阅事实。
- 鉴权 lease 与 driver capability 分离：lease 负责身份/续期，driver capability 负责输入/取消/审批控制权，可撤销、可显式移交。
- `state`、`projections`、`interactions`、`subscriber_ids` 不能暴露可变引用。
- store append 成功后才更新 projection；projection 更新成功后才发布 live event。
- actor 可被 unload，但只有 idle、无 pending interaction、无 writer 且无存活直接子代理时才允许。这里的 `idle` 只适用于 `AgentKind::Session` 且其 child set 为空；子代理 worker 不进入全局 idle-unload 候选集。
- 父 `Unload`、`SessionDeleted` 与 daemon shutdown 必须沿 parent/child edge 先停止 child admission，再取消并 join 整棵 child 树；未全部进入终态前不得确认父卸载，也不得写父 tombstone。v2.0 不提供隐式 detach；若未来支持 detach，必须写显式事实并转移 owner，不能只删除内存 edge。
- v2.0 可保留每 session OS thread 作为迁移桥；目标逐步改为 async actor + blocking pool，禁止 thread-local 隐式 workspace/sandbox。

### 5.2 TurnCore 只做决策

```rust
pub enum TurnInput {
    UserInput(UserInput),
    ToolResult(ToolOutcome),
    InteractionResolved(InteractionResolution),
    SystemInjection(SystemInjection),
    InterAgent(InterAgentMessage),
    CompactionResult(CompactionResult),
    Cancel(CancelRequest),
}

pub enum TurnDirective {
    CallGate(GateRequest),
    ExecuteTools(ExecuteBatch),
    ResumeInteraction(ResumeInteraction),
    WaitForInteraction(PendingInteraction),
    Commit(CommitIntent),
    Compact(CompactionRequest),
    Finish(TurnTerminal),
}

impl TurnCore {
    pub fn step(&mut self, input: TurnInput) -> Vec<TurnDirective>;
}
```

规则：

- TurnCore 无 `await`、无文件/网络/线程/锁。
- `TurnState` 使用私有 transition API 的 enum 状态机，不上全量 typestate。
- 状态至少包含 `Idle`、`Running`、`WaitingInteraction`、`Compacting`、`Terminating`。
- 同一时刻最多一个 active turn；终态只能进入一次。
- 取消是 `TurnInput::Cancel` + `CancellationToken` 树，不是多个 `user_cancelled` 布尔值。
- compaction、title、liveness、session lifecycle 是 actor/task port，不内联进 loop。
- TurnCore 只产生 `CommitIntent`，不直接 append fact，也不直接发布 projection；actor 统一执行“append -> fsync -> apply projection -> publish”。
- interaction resolution 是输入，不是直接恢复未来；只有 `approved` decision 才能构造 `ResumeInteraction`，`rejected/expired` 直接映射到 `denied/cancelled` 终态。ToolRuntime 的 resume admission 必须是 actor 串行临界区内的原子 CAS：重新检查该 `call_id` 尚无 `ToolIntent`/`ToolFinished`、decision 仍有效、turn/cancel 未终止，并在同一临界区提交 `ToolIntent` 后才允许 handler 启动。
- pending call 必须跨 actor unload/restart 保留在 fact/registry 中；permission/ask/plan 都在 `ToolIntent` 之前挂起，因此只有“无 `ToolIntent`、无 `ToolFinished`”的 call 可在 resolution 后进入执行。`ToolFinished::Indeterminate` 与其他终态一样不可逆，恢复后禁止再次执行。
- cancel 与 interaction 必须一起闭合：若 cancel 使 pending permission/ask/plan 失效，actor 必须先提交 `InteractionExpired { reason=turn_cancelled }`（或已有 decision 对应的 `InteractionResolved`），再提交唯一 `ToolFinished`。已有 `ToolFinished` 的 interaction 不得继续作为 pending modal 重放。

### 5.3 Gate 与工具边界

```text
TurnCore
  └─ CallGate(GateRequest) ──► GateHost ──► provider
                                  │
                                  └─ GateOutcome::Tools | Text | Suspend | Abort

TurnCore
  └─ ExecuteTools(ExecuteBatch) ─► ToolRuntime
                                     ├─ policy admit
                                     ├─ sandbox
                                     ├─ schedule by capabilities
                                     ├─ execute handler
                                     ├─ progress/audit
                                     └─ BatchOutcome
```

- Gate 负责协议转换、重试、流解析、错误分类；不负责工具权限。
- ToolRuntime 负责 admit、并发分区、串行降级、超时、取消、线程、进度、审计和事件 effect。
- TurnCore 只消费 `BatchOutcome` 并决定 `WaitForInteraction`、`Finish` 或下一轮。
- `ExecuteBatch.calls` 必须是未授权 candidate；admit 在 ToolRuntime 内，否则无法产生权限 pending。

### 5.4 子代理生命周期、消息与配额

`SubagentSpawned/Finished` 是 parent log 上的 edge；child 仍拥有自己的 canonical log，但不拥有独立生命周期根。所有权规则如下：

- `SubagentRegistry` 由直接 parent `SessionActor` 持有，但 daemon 级 `SubagentSupervisor` 持有进程内 child handle 的兜底所有权；parent actor panic 时由 supervisor 按 canonical edge 取消并 join 整棵 child 树。
- spawn 采用两阶段：先创建并 durable 写 child `SessionCreated`，再 durable 写 parent `SubagentSpawned` edge，最后 child 才能接收第一条输入。恢复时同时扫描“edge 无 child log”和“child log 无 edge”：前者是完整性损坏，parent 进入 read-only/upgrade-required，禁止伪造 child 或终态；后者 tombstone/取消孤儿 child。若 child 已 terminal 而 parent edge 未闭合，恢复必须用 `RecoveryStep::SubagentFinished` 幂等补齐；`RecoveryPlan.child_terminal_digest` 必须覆盖 `child_session_id`、`child_log_id`、`terminal_fact_seq`、`terminal_event_id`、`status`、`parent_call_id`、`result_ref`、`finished_at_ms` 八个字段，并与 spec 的 digest 集合一致。
- child 的运行、取消、mailbox、工具预算和审计归属都在 parent/child 树中可查询。child 的 `SubagentFinished` 与 actor join 完成后，parent 才写对应 edge 终态；parent log 与 child log 不复制对方事实。child terminal 只从 child committed high-water 映射，`timed_out` 固定由 `TurnFinished { terminal=failed, error.code=subagent_timed_out }` 产生。
- `input_purpose=queue_only` 只投递并持久化 inter-agent message，不触发 child turn；`input_purpose=trigger_turn` 只在 child idle 时启动 turn，否则排队，禁止并发创建第二个 active turn。消息必须携带稳定 `message_id/input_id`；child durable 写 `InputAccepted` 后，只有 `trigger_turn` 必须在同一 admission 流程写 `TurnStarted`（或在崩溃恢复时按 `input_id` 恰好补一次 `TurnStarted`）才能向 parent ack。parent 在收到 durable ack 前不得删除 pending message；已有 `InputAccepted` 无 `TurnStarted` 不得被永久去重为空操作，但 queue-only 不得被恢复逻辑补成 turn。
- child 的工具调用继续使用同一 Policy/Sandbox/ToolRuntime 契约，副作用以 child `session_id/call_id` 归属，并通过 `parent_call_id` 与 parent edge 建立因果链。
- root session 树只有一个 `QuotaLedger` owner（由 root `SessionActor`/`SubagentSupervisor` 担任）；spawn、mailbox、content 和工具预算必须先做原子 durable reservation，child 只能消费已预留 bucket。账本固定为 `{data_dir}/quota/{root_session_id}/ledger.jsonl`，使用独立 `quota.lock` 串行化 root 与全部 child 的 append，不能用 per-session `writer-fence.json` 代替。记录使用稳定 `reservation_id` 和 append-only `reserved -> committed/released` 记录（含 root/child identity、kind、amount、canonical key），重启时按 canonical facts 与 content index reconciliation：无 child edge 的 reservation 释放，已提交量重算，禁止只依赖内存计数；soft/hard watermark 到达时拒绝新 spawn 或高成本工具，child 不得绕过 parent 配额。账本不随 child close/delete/cutover 删除。
- parent `SessionDeleted` 必须级联 tombstone child tree；child canonical log 不能在缺少 parent edge 时被独立打开或列出。v2.0 不允许 child 脱离 parent 成为独立 session；显式 detach/transfer 留给后续版本。

## 6. ToolRuntime 与 Typed Tool SDK

### 6.1 执行契约

```rust
pub struct ExecuteBatch {
    pub turn_id: TurnId,
    pub round_num: u32,
    pub calls: Vec<ToolInvocation>,
    pub context: BatchContext,
}

pub enum ToolCallState {
    Pending { call_id: ToolCallId },
    Running { call_id: ToolCallId, execution_id: ExecutionId },
    Finished { call_id: ToolCallId, outcome: ToolOutcome },
}

pub struct BatchOutcome {
    pub states: Vec<ToolCallState>,
    pub pending_interactions: Vec<PendingInteraction>,
    pub fatal: Option<FatalToolError>,
}
```

- `ToolOutcome` 必须携带 `call_id/turn_id/execution_id`，不能靠队列位置反推调用身份。
- `states` 与输入 call 一一对应，但允许 `Pending/Running`；只有 `Finished` 是终态。
- 每个 call 最终必须恰好进入一次 `Finished`。只有尚无 `ToolIntent` 且尚无任何 `ToolFinished` 的 permission/ask/plan call 才能在 `approved` decision 后经 `ResumeInteraction` 继续执行；resume admission 与 `ToolIntent` append 必须在 actor 串行临界区内原子完成，已有 `Indeterminate` 或其他终态时只返回原终态。
- cancel 先于 resume admission 生效时必须闭合 interaction 并写 `Cancelled` 终态；一旦 `ToolFinished` 已提交，后续 resume 只能返回既有终态，不得先 append `ToolIntent` 再执行。
- `pending_interactions` 由 actor 写入 `InteractionRegistry` 并挂起 turn。
- `fatal` 已负责 seal 对应 timeline block，loop 不再重复发射。
- 结果按模型 call 顺序回填，执行并发不改变模型序。

### 6.2 ToolCapabilities 是调度唯一依据

```rust
pub struct ToolCapabilities {
    pub concurrency: Concurrency,      // Parallel | Serial | Exclusive
    pub streaming: bool,
    pub cancel_grace: Duration,
    pub idempotent: bool,
    pub workspace_bound: bool,
    pub side_effects: SideEffectClass,
}
```

- 删除 `serial_call_ids`、名字表、exec 特例和静态/动态两套注册表。
- 生产 `ToolManager` 必须注册 `ErasedTool` + `ToolDescriptor`，启动时校验名称碰撞、schema 和 capability 合法性。
- 未迁移工具通过 `LegacyToolAdapter` 接入；adapter 必须显式返回 host effects，不能丢弃 skill effects。

### 6.3 Typed output 与四投影

```text
TypedTool::run(args) -> ToolOutput<O>
                         ├─ model projection
                         ├─ display projection
                         ├─ resource effects
                         └─ service projection
```

规则：

- `ToolOutput<O>` 是 canonical output；`ToolProjection` 负责 model/display。
- `WorkspaceEffect` 只描述业务变化，由 SessionActor 转成 `WorkspaceResourceChanged` fact。
- service 与工具共用 projector，不共用写 handler。
- summary 禁止 JSON；display 缺失时 client 必须完整回退旧字段。
- MCP/LSP 保持宽容 envelope，但仍经统一 outcome/truncation/metrics。
- `ToolResult` 保留为迁移 wire；新能力通过 additive 字段和 typed `data.payload` 进入。

### 6.4 执行保证：at-most-once + reconciliation

必须新增 durable execution ledger，不能把 call_id 或 `SeenIds` 当保证。默认保证是 **at-most-once**；只有声明 `idempotent=true` 或实现 reconciliation 的工具才可达到 exactly-once 级语义：

```text
1. validate call
2. append audit intent + durable barrier
3. append ToolIntent { call_id, idempotency_key, args_hash } + independent fsync barrier
4. execute under policy/sandbox
5. append audit result + durable barrier
6. append ToolFinished { call_id, terminal_status, output_ref } + independent fsync barrier
7. update projections / emit events
```

恢复规则：

- 有 `ToolIntent` 无 `ToolFinished`：
  - `idempotent=true` 且无副作用：可重放；
  - `idempotent=false`：写 `ToolFinished::Indeterminate`，禁止自动重跑；
  - 支持 reconciliation 的工具可查询外部结果，但必须由工具显式声明。
- `ToolFinished::Indeterminate` 是不可逆终态；同一 `call_id` 后续收到 `ResumeInteraction`、重复 tool result 或恢复输入时，只能返回该终态，禁止再次 admit/execute。
- `ResumeInteraction` 只能携带有效 `approved` decision；rejected/expired/cancel 直接闭合 interaction 与 call。任何实现都不得用“先查一次、后执行”的非原子 gate 替代 actor 内的 terminal/decision/cancel CAS。
- 取消也必须写 `ToolFinished::Cancelled`，不能只写内存取消标志。
- 同一 `call_id` 的重复输入返回已有终态，不再次执行；任何恢复路径都不得为同一 call 追加第二个 `ToolFinished`。

## 7. Policy、Sandbox 与审批

### 7.1 三层决策链

```text
ToolRequest
  └─ PolicyEngine.decide()
       ├─ Allow  ──► SandboxSpec ──► execute
       ├─ Deny   ──► ToolRejected
       └─ Ask    ──► InteractionRequested
                         │
                         └─ approve ─► one-time grant ─► execute
```

- `PolicyEngine` 输入是显式 `ToolCallContext`，不读 thread-local。
- 规则输出 allow/deny/ask/amend；四级档位只作为规则 preset。
- OS sandbox 是最终执行边界；规则引擎不能替代 sandbox。
- 审批凭证只对单次 call/scope 有效；“记住决定”写 amend rule，不复制凭证。
- sandbox denial 后可进入一次 escalation approval；不得静默绕过。

### 7.2 SandboxSpec

```rust
pub struct SandboxSpec {
    pub mode: SandboxMode,
    pub writable_roots: Vec<CanonicalPath>,
    pub read_deny: Vec<PathPattern>,
    pub network: NetworkPolicy,
    pub env_allowlist: Vec<String>,
    pub path_policy: PathPolicy,          // symlink/device/FIFO/UNC/Windows device
    pub fd_policy: FdPolicy,              // openat/O_NOFOLLOW/fd-relative rename
    pub process_limits: ProcessLimits,    // pid/fd/cpu/memory/wall/process-group
    pub platform_fallback: PlatformFallback, // fail_closed | explicit_bypass
}
```

安全不变量：

- 授权对象与执行对象必须是同一 canonical identity；symlink/device/FIFO/TOCTOU 必须在 open/rename/unlink 边界处理，不能只在参数解析时检查。
- 路径写操作默认使用 fd-relative、`O_NOFOLLOW`、目录句柄等抗 TOCTOU 原语；无法保证的平台必须 fail-closed。
- read 不得无界读取设备/管道/特殊文件；write 不得通过设备节点或符号链接逃逸。
- 每个 exec 工具必须有 process-group、fd、CPU/内存/墙钟上限；网络按目标/端口/代理策略限制。
- Windows 必须覆盖设备路径、UNC、junction/reparse point；未覆盖前不得声明与 Linux 同级沙箱。

v2.0 第一刀：

- Linux：Landlock/bwrap + process-group/network policy。
- macOS/Windows：先保持显式 unsupported/fail-closed 或进程硬化，不虚假宣称 OS sandbox。
- `Level 4 exec 可逃逸 workspace` 不再是默认能力；必须成为显式 bypass preset + 审计事件。
- audit 对 write/exec/net 默认 fail-closed；只读工具可按配置 fail-open 并记录告警。
- 有副作用工具先写 `decision/audit intent`，再执行；结果/拒绝/失败都要记账。audit barrier 失败时不得进入 handler。
- audit result 写失败且副作用已发生时，不得宣称回滚；必须进入 quarantine/emergency sink、停止后续写操作，并把工具结果标记为 `Indeterminate`。

### 7.3 InteractionRegistry

- 键为 `interaction_id`，关联 `call_id`、`turn_id`、`kind`。
- permission/ask/plan 全部持久化 `InteractionRequested/Resolved`。
- first-answer-wins；重复 resolution 返回既有结果，不重新挂起。
- 重连只重发未决 interaction；已 resolved 的 interaction 不回放 UI modal。
- TUI/Web 必须维护 `resolved_interaction_ids`，不能只靠本地 modal 状态。

## 8. 持久化、恢复与重连

### 8.1 写入协议

```text
SessionActor
  -> SessionStore.append(fact)
       -> writer lock check
       -> JSONL append
       -> fsync/barrier
       -> ProjectionSet.apply(fact)
       -> publish ProjectionEvent
```

- 一个 session 同时只能有一个 writer；跨进程使用 `events.lock` 做 OS 级互斥，但锁文件不是 ownership 事实源。每次 append 前必须按 schema spec 校验 `writer-fence.json` 的 `writer_id/generation_epoch/fencing_token/log_id/lease`；迁移、cutover、恢复接管会推进 epoch/token，旧 writer 收到 `stale_writer` 后必须停止 handler 与写入。
- root 树 quota ledger 是唯一的跨 session 写例外：它由 root owner 持有 `quota.lock`，不进入 `SessionActor` 的 per-session writer 临界区，也不受 child `writer-fence.json` 约束；reservation 的 durable ack 必须先于 spawn/content/tool 副作用。
- `fact_seq` 的分配与 durable commit 必须在同一个单 writer 临界区内完成：每个 barrier segment 先按提交顺序预留连续区间，完整写入 segment 后再执行 `fsync`，只有 barrier 成功后才提交内存 `committed_seq`、apply projection 与发布事件。临界区外不得预分配 `fact_seq`。
- group commit 按 durable barrier 分段，而不是把整个 actor batch 强行合并成一次 `fsync`：barrier fact 必须先 flush 其前置普通 facts，再单独 fsync；同一 actor batch 可以包含多个 segment/多个 fsync。
- crash 后先读取 `events.commit.json` 并截断到 committed offset，再从该 prefix 恢复下一 seq。未写入 commit marker 的完整行仍属于未提交 segment，可被丢弃/复用；不得为了隐藏失败提交而跳号或留洞。每次 barrier 成功后必须先 durable 更新 `events.commit.json`，再推进 `content/clock.json`、发布/ack；commit marker 更新失败或 `fsync` 返回失败时 writer 立即进入 `CommitRecoveryRequired`，保持 commit high-water 不变，写 `events.poison.json` 证据并截断回 committed offset。`CommitRecoveryRequired` 只允许 recovery/repair 路径处理，禁止复用 `ReadOnlyUpgradeRequired`，也不得发布/ack。启动时若 `events.jsonl` 超过 commit offset，一律先截断，禁止把失败 segment 的完整前缀当 canonical；若 marker 缺失但 JSONL 完整且可由最后完整行安全重建，则先写 recovery evidence/audit 再重建 marker，否则保持 recovery-only。
- 尾行撕裂：保留不可覆盖的 `.torn` 证据，截断到最后完整记录，再写 `SessionRecovered` fact。torn 文件名至少包含 `(fact_seq, bytes_hash)` 或等价唯一身份；同路径冲突时必须追加 hash/offset 后重新命名，禁止覆盖已有证据。
- 派生 snapshot 用 temp + rename；损坏时从 `events.jsonl` 重建。
- `events.jsonl` 不重写、不压缩原地；归档/轮转通过 manifest 或新段，不能破坏 `fact_seq`。
- 无副作用 fact 可以 group commit；`ToolIntent`、`InteractionResolved`、`InteractionExpired` 和所有 `ToolFinished` 必须各自使用独立 durable barrier，不能被无副作用 group commit 吸收。
- 大内容先写 `content/<hash>` 并 fsync，再 append 引用它的 fact；content 写入失败时不得执行对应副作用或必须写 `Indeterminate`。
- ContentStore 采用 mark-and-sweep GC：从活跃 facts/compaction checkpoint 标记，旧 ref 只有越过保留窗口后才能删除。
- 每 session 事件缓冲和每 client 发送队列必须有界；慢客户端达到高水位时先断开并让客户端走 `ResetRequired`，不能拖垮 actor。
- 初始容量基线（必须可配置并有测试）：actor mailbox 1024、per-connection queue 256、replay buffer 16 MiB、progress buffer 8 KiB/50 ms、单 fact 64 KiB、content 总量按 session 配额。溢出策略只能是显式 disconnect/reset/拒绝，不得静默丢 reliable fact。
- ContentStore、derived snapshots、旧 events 段都必须有 retention/GC/disk quota 指标；容量达到阈值时先降级非关键 projection，再阻止新的高成本工具，而不是 OOM。

### 8.2 崩溃恢复状态机

启动/加载时，从最后一个完整 fact 重建 projection，然后按以下状态闭合：

| 恢复输入 | 恢复动作 | 写入的恢复 fact |
|---|---|---|
| `InputAccepted(input_purpose=trigger_turn)` 无 `TurnStarted` | 按稳定 `input_id` 补唯一 turn；`queue_only` 不进入本行 | `TurnStarted` + final `SessionRecovered` |
| `TurnStarted` 无 `TurnFinished/Interrupted` | 未 seal 流丢弃，turn 标记 interrupted | `TurnInterrupted` |
| `ToolIntent` 无 `ToolFinished`，工具幂等 | 允许重放执行 | 最终 `ToolFinished` |
| `ToolIntent` 无 `ToolFinished`，工具非幂等 | 禁止重跑，标记不确定；该 call 从此不可 resume | `ToolFinished::Indeterminate`（唯一终态） |
| `InteractionRequested` 无 `Resolved` | 仅无 `ToolIntent`/`ToolFinished` 时保留 pending，可重连/超时；否则返回既有终态 | `InteractionExpired` 或等待 resolution |
| `CompactionApplied` 无 checkpoint | 从 active facts 重建 context | `SessionRecovered` |
| 尾行撕裂 | 保留 `.torn`，截断到最后完整行 | `SessionRecovered` |
| `events.poison.json` 或日志超过 commit offset | 按 `events.commit.json` high-water 验证/截断失败 segment | `CommitRecoveryRequired`；只允许 repair 路径，修复前不得发布/ack |
| 同 schema 未知 fact kind | session 进入 read-only/upgrade-required；普通未知字段忽略，不触发此路径 | `SessionRecovered(read_only_upgrade_required)`；不得追加业务 fact |
| 未知 payload version | 旧 writer 不解释未知 fact 及其后缀；升级 writer 验证整条日志后先推进 `upgrade-fence.json`，再恢复 | 旧 writer 只写 `SessionRecovered(read_only_upgrade_required)`；升级 writer 写新的 `SessionRecovered(writable)` 或版本迁移 fact；旧 writer 不得覆盖更高 generation 的 writable fence |

恢复状态机必须可重复执行：同一输入重复恢复不得产生两个终态，`SessionRecovered` 只写一次。恢复期间若发现同一 `call_id` 已有 `ToolFinished`，无论其状态为何都不得再次执行该 call；`Indeterminate` 的后续 resolution 必须返回原终态。升级恢复必须使用新的 recovery identity，不能覆盖旧 read-only batch；`SessionRecovered` 之后若有新的 open state 或 pre-recovery log 已变化，才允许创建新 batch。

### 8.3 重连协议

客户端订阅请求：

```json
{
  "session_id": "...",
  "since_cursor": {
    "log_id": "...",
    "fact_seq": 123,
    "projection_index": 2
  },
  "capabilities": ["reliable_replay", "interaction_replay"]
}
```

服务端状态机：

```text
Reconnect(since_cursor)
  ├─ log_id mismatch / cursor expired
  │    -> ResetRequired { log_id, snapshot_cursor }
  │    -> client fetch bootstrap(projection at snapshot_cursor)
  │    -> subscribe(since_cursor = snapshot_cursor)
  └─ in window
       -> actor command: subscribe + replay atomically
       -> send ProjectionEvent::Reliable where
          cursor.log_id == since_cursor.log_id and
          (fact_seq, projection_index) > since_cursor (字典序)
       -> live ProjectionEvent buffered during replay
       -> dedupe by (log_id, fact_seq, projection_index)
       -> live
```

不变量：

- snapshot baseline 与 subscribe 必须在 actor 串行点原子化。
- replay 只回放 `Delivery::Reliable`；`Replaceable` 只给当前值，`Ephemeral` 不回放。
- 多个 reliable `ProjectionEvent` 可复用同一 `fact_seq`，必须用 `projection_index` 区分并按复合 cursor 排序。
- `ResetRequired` 必须带 `log_id` 与 `snapshot_cursor`，客户端不能拿旧 snapshot 覆盖新流。
- pending interaction 按 `interaction_id` 重放，first-answer-wins。
- 断线期间不承诺逐 token 回放；最终 transcript 由 facts 重建。

### 8.4 多客户端

- `subscription`：连接能收到哪些 session event。
- `driver`：谁有控制权提交输入/取消/审批；是显式 capability lease。
- `request_id`：连接级命名空间，服务端回复原 request id。
- 共享 interaction 广播给所有具备 `interact` capability 的订阅者；first-answer-wins。
- driver 断线后按显式优先级/最近活跃度/能力移交，并写 `DriverChanged` projection event。
- lease 只表示鉴权/身份/续期，不再承担 session ownership。

## 9. Client 与 TUI 架构

### 9.1 `qaqh-client` 稳定 API

```rust
pub trait SessionClient {
    async fn open_session(&self, req: OpenSession) -> Result<SessionHandle>;
    async fn subscribe(&self, req: Subscribe) -> Result<Subscription>;
    async fn command(&self, cmd: ClientCommand) -> Result<CommandAck>;
    async fn query(&self, query: TypedQuery) -> Result<TypedResponse>;
}
```

要求：

- service request/response 全 typed，禁止 `serde_json::Value` 进入 App。
- `ServiceError { code, message, retryable, hint }` 原样传给 UI。
- subscription 事件携带 `log_id`、`seq`、`revision`、`stream_key`。
- 单一 reconciler 管理 attach/bootstrap/subscription，不再由 App 和 Runtime 双所有权。
- `ResetRequired` 是正常状态迁移，不是错误 toast。

### 9.2 TUI 三层模型

```text
WireModel       qaqh-client 类型；只反序列化/兼容判定
SessionModel    canonical reducer；记录 log_id/last_seq/revision/interaction_id
ViewModel       timeline/tool/resource view；稳定 ID、纯函数、可测试
Presentation    scroll/focus/expand/overlay/animation；不进 wire/render cache key
```

- 一个 seed 一个 `SessionModel`，reducer 必须幂等并拒绝旧 epoch/seq/revision。
- `bootstrap`、live event、service response 都进入同一个 reducer；旧响应不得回滚新状态。
- ToolView/ResourceView 只构造一次，render/export/activity bar 共用。
- `display` 为 `None/Unknown` 时完整回退，不允许部分解析新字段。
- 渲染继续使用 block-level cache；动画不进缓存；只重渲脏块。

### 9.3 迁移后的前端验收

- 展示路径 `serde_json::from_str` 为 0（无兼容豁免）。
- TUI 不读取服务端 journal/checkpoint/offload 布局。
- `since_cursor` 重连、`ResetRequired`、pending interaction replay 有 fixture。
- 子代理 seed 在 rebaseline 后仍能从 canonical tool output 恢复，不能依赖 UI ToolCard 反推。
- CI 固定 backend rev 与实际 v2 wire contract 同步。

## 10. 进程与部署模型

### 10.1 v2.0 裁决

**保留 `qaqh-daemon` + 客户端两进程模型。** 原因：

- 现有产品已经支持多客户端，daemon 是稳定部署面；
- 当前 v2 的主要风险是状态/存储边界，不是进程数量；
- 单二进制 embedded 会同时引入依赖环、构建体积和 UI/runtime 生命周期问题。

但 v2.0 必须做到：

- 所有 embedded/remote 共用同一 `SessionCommand/ProjectionEvent` 语义；
- transport 可替换，不能让 HTTP/SSE 类型进入 runtime；
- TUI 不直接依赖 runtime，只依赖 `qaqh-client`；
- daemon 的 connection/subscription 生命周期可独立测试。

### 10.2 v2.1 候选

若产品需要“单文件启动 + 崩溃隔离”，再引入：

```text
qaqh composition root
  ├─ qaqh tui          -> embedded NodeHandle 或 local daemon
  ├─ qaqh daemon       -> detached daemon
  ├─ qaqh exec         -> headless
  ├─ qaqh app-server   -> UDS/stdio
  └─ qaqh doctor
```

embedded 必须复用同一 app-server 语义；不得复制一套 session/approval 逻辑。

Gate：从 events 重建的 projection 与旧快照行为等价；删除 derived snapshot 后能重建；无双写漂移；单 writer facade 通过并发测试。

### P2：SessionActor 与 TurnCore

1. 把所有输入、取消、审批、订阅路由到 SessionActor mailbox。
2. 抽 `TurnCore::step`，用 1:1 wrapper 包住现有 run_lap。
3. 将 compaction/title/liveness/session lifecycle 移出 loop。
4. 统一取消为 token 树 + 单一终态。
5. 逐步去掉 thread-local workspace/sandbox 和 `user_cancelled` 多份状态。
6. 引入 daemon 级 `SubagentSupervisor`，把 parent/child cancel/join 从 `registry.close` 的裸 unlink 改为 canonical edge 驱动；覆盖 parent panic、SessionDeleted、shutdown 与 spawn 竞态。
7. 实现两阶段 spawn 恢复扫描（edge/child log 双向孤儿）、inter-agent message `message_id/input_id` 去重，以及 `{data_dir}/quota/{root_session_id}/ledger.jsonl + quota.lock` 的 root `QuotaLedger` reservation/reconciliation。

Gate：turn lifecycle、cancel、suspend/resume、compaction 行为契约测试全绿；同一时刻最多一个 active turn；终态只发一次。子代理最小切片必须包含 `parent_unload_waits_child_terminal_join`，顺序固定为 `child terminal -> parent SubagentFinished -> child join -> parent unload ack/tombstone`；quota 不与该顺序合并判定。

### P3：ToolRuntime 与 Typed Tool SDK

开工前置：显式 `ToolCallContext` 必须已注入 workspace/session/cancellation/sandbox 信息；不能沿用 thread-local，否则 LegacyToolAdapter 路径会读空 workspace。

1. 生产 ToolManager 注册 `ErasedTool`，移除字符串 handler 注册表。
2. 把 admit、并发调度、超时、取消、进度、审计搬入 ToolRuntime。
3. 接入 `ToolIntent/ToolFinished` ledger、at-most-once 恢复、actor 内 resume/terminal/cancel 原子 CAS 和故障注入；`Indeterminate` 必须能被 runtime 查询并拒绝再次执行。
4. 以 todo 为第一个 typed output 试点，再迁移 skills/plan/process/subagent。
5. service 与工具共用 projector；删除 JSON 字符串错误路径。
6. 把 permission/ask/plan cancel 与 `InteractionExpired/Resolved` 的提交顺序纳入同一 actor transition，禁止 terminal 后重放 pending modal。

Gate：tool ordering 行为不变；每个 call 恰好一个终态；非幂等工具崩溃不重跑；display/model/resource/service 同源；TUI JSON 考古归零。

### P4：Policy 与 Sandbox

1. 抽 `qaqh-policy`，四级档位变为 preset。
2. 所有工具通过显式 `ToolCallContext` 获取 workspace/mode/grants。
3. Linux OS sandbox 第一刀；unsupported 平台 fail-closed 或显式降级。
4. approval 接入 InteractionRegistry；一次性 grant + amend rule。
5. audit 改为 write/exec/net fail-closed，引入唯一 `AuditWriter` + durable `sync_data` ack，补留存/查询/签名锚点。

Gate：权限全表矩阵、sandbox deny/escalation、审批重放、audit chain/torn/rotate 全绿。

### P5：Ringing v2 与 Client/TUI

1. 新增 Ringing v2 端点和 `since_cursor` 原子订阅；补 v1 `Last-Event-ID` 映射表。
2. v1 `Last-Event-ID` 做兼容映射；replaceable 不推进 cursor。
3. `ResetRequired`、pending interaction replay、driver capability 进入 client API。
4. TUI 在既有 M1-M3 成果上完成单 SessionModel reducer、rebaseline watermark/epoch 防护和 interaction 幂等；不重做已完成的 block cache。
5. 渲染管线补齐 dirty/throttle、剩余 ToolView/H16 清理和 resource view。

Gate：断线/重启/多客户端 replay 等价；无 gap/dup；interaction first-answer-wins；TUI 快照不倒退。

### P6：清理与可选 composition root

1. 删除三频道 journal、latest checkpoint、独立 timeline 事实快照、offload 重复存储。
2. 删除 legacy service JSON、旧 tool display 解析和 thread-local 路径。
3. 归档/迁移旧目录；按 §4.4 的消费者判据处理 `timeline-audit`；quota ledger 按 root 保留规则单独迁移，不能随 session 目录删除。
4. 评估单 binary embedded/remote composition root。

Gate：canonical log 单源、旧目录可迁移、无兼容豁免残留；embedded/remote 若引入则共用同一语义测试。

## 13. 明确拒绝的方案

1. **每频道一份物理 journal**：频道是过滤视图，不是存储分区。
2. **持久化 per-client cursor/lease/checkpoint**：连接状态全内存化；cursor 由客户端携带。
3. **timeline/offload/chat_history 作为第二事实源**：它们只能是派生缓存。
4. **工具直接发 domain event**：工具只返回 output/effect，由 actor 统一提交。
5. **loop 直接 spawn 工具线程、泵进度、审计**：全部归 ToolRuntime。
6. **把 call_id 当 exactly-once**：必须有 durable intent/result ledger。
7. **照搬 Codex Guardian V2 / shell escalation**：v2.0 不做，成本高且前置条件未满足。
8. **照搬 Grok per-session OS thread + unbounded channel + leader**：先解决 actor 状态和背压，再评估进程模型。
9. **在 v2.0 同时做单二进制 embedded**：会让状态边界问题与进程/构建问题叠加。
10. **永久双写旧字段/旧目录**：只允许明确期限的观测期，必须有删除 gate。

## 16. 最终判断

当前结论必须分两层：架构方向与 P0 文档已经冻结，canonical types 与 golden fixtures 已由 PR #115 落地，但 canonical log、SessionActor、ToolRuntime 等生产运行时路径尚未实现。PR #104 已合并为 `84adf01`，`session-fact-v2` 与本计划可以标记为文档冻结，但不得把 I1-I18 的 E3 目标描述成已完成。

QAQH v2 的核心不是“再写一套 Ringing v2”，而是完成一次所有权重组：

- 把历史所有权从多个 journal/snapshot/offload 收回到 `events.jsonl`；
- 把 session 状态所有权从 loop/多个线程局部收回到 `SessionActor`；
- 把工具执行所有权从 TurnEngine 收回到 `ToolRuntime`；
- 把输出所有权从字符串/JSON 收回到 typed `ToolOutput`；
- 把前端状态所有权从多路合流收回到单 `SessionModel` reducer。

只有这五个所有权边界建立后，重连、多客户端、审批、沙箱、子代理、渲染和审计才可能各自独立演进，而不再互相补丁。
