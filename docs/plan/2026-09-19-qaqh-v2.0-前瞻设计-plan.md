# QAQH v2.0 前瞻设计纲要

> 日期：2026-09-19 · 状态：**讨论稿**（v2.0 设计启动输入，非最终设计）
> 输入来源：v1(dsx)→v2 演进复盘、codex / grok-build 对标分析、agent loop 与 ringing 专项取证
> 用法：本纲要只定"方向、边界、验收"；正式设计以随后冻结的三份 spec（见 §6）为准。

---

## 0. 一句话目标

v1 靠「约定 + 启发式 + 字符串」，v2 换成了「协议 + 状态机 + 类型」——方向正确；但代价是**防御性补丁沉积**与**职责内联**（Loop 51 方法、ringing 每 seed 9 类产物）。

**v2.0 的任务：用「不变量 + 归位」替换 v2 的「补丁 + 内联」。不新增产品能力，只收敛结构。**

## 2. Ringing v2.0（前后端协议）

### 2.1 现状取证（为什么说臃肿）

`~/.config/qaqh/ringing`，3 个活跃 seed：**19 目录 / 903 文件 / 42MB**。单 seed（d9a1a320）：

| 产物 | 大小 | 性质 |
|---|---|---|
| `journal/{control,conversation,tool}/{seed}.jsonl` | 0.4 + 1.1 + 1.05 MB | 3 条频道各一份可靠事件日志 |
| `latest/{channel}/{seed}/{hash}.json` | ~620B × N（conversation 一个 seed 积到 **780** 个） | replaceable 流身份一个 checkpoint，**不清理** |
| `ringing-timeline/{seed}.json` | 3.4 MB | timeline 完整快照（单 JSON 反复重写） |
| `ringing-offload/{seed}.jsonl` | 2.1 MB | 大内容外置（与 timeline 记录重叠） |
| `timeline-audit/{seed}.jsonl` | 2.0 MB | 审计副本 |

会话本体 `sessions/{seed}/`（messages.jsonl + wal + meta + todo + outbox）**仅 1.3MB**。
→ 同一批事实存了 **6-7 份**，ringing ≈ canonical 的 **8 倍**。

### 2.2 对标结论（codex / grok-build，两家都面对断线重连）

**三条共识**（详见附录 A）：

1. **事件流不持久化，历史持久化**：codex = rollout JSONL（每 thread 一个 append-only 文件）+ sqlite 索引；grok = `updates.jsonl`（唯一事实源）+ `chat_history.jsonl`（**可重建的派生缓存**）。两家都没有 per-channel journal、没有 per-client 持久游标、没有 checkpoint 目录。
2. **重连 = 重放/投影 + 原子订阅**：
   - codex：`thread/resume` 返回**投影历史**（分页 cursor）+ **原子订阅**（同一序列化点，无缝隙 → 不需要事件重放）；断线期间错过的 live 通知**不重放**。
   - grok：`session/load` 从**同一份 log 流式重放**给加载中的客户端（单播 + `event_seq` 去重，"replay-overlap dropped"）。
3. **只重放"阻塞请求"**：审批 / ask / plan 这类"客户端欠一个回答"的未决请求，重连时按 call_id 重放（codex `replay_requests_to_connection_for_thread`；grok pending modal 缓存）；其余通知断线即弃。订阅集合 / driver 归属**全在内存**（grok 断线时 driver 移交下一个订阅者）。

### 2.3 v2.0 目标形态

```text
每 seed（磁盘）:
  events.jsonl          ← 唯一 canonical，append-only，单写者
  derived/              ← 可重建缓存（timeline 快照 / chat history 投影）
  meta.json / todo.json ← 小状态文件（原子写）

进程内（内存）:
  subscriber sets / client cursor / pending interactions / lease

重连协议:
  客户端带 since_seq
    → 服务端从 events.jsonl 重放（live 期间缓冲）
    → seq 去重（重叠丢弃）
    → 原子订阅（此后 live 直发）
  未决阻塞请求按 call_id 重发
```

**四条设计决定**：

- **D1 频道 = 过滤视图，不是存储分区**：control/conversation/tool 三频道保留在 wire 上，但物理上合并为一份 log。
- **D2 replaceable 流不落盘**：streaming 增量不写 checkpoint；重连时从 log 尾部 peek 最后 in-progress 状态（对齐 grok `replay.rs` 的 line-peek 模式）。
- **D3 投影不持久化为"事实"**：timeline 快照降级为可重建缓存（temp+rename，损坏即重建）；offload 并入 canonical log（内容以 ref 引用）；audit 独立且可关闭。
- **D4 订阅/游标/租约内存化**：服务端不再为每个客户端保留持久状态；重连由客户端携带 cursor 驱动。

### 2.4 前端契约影响清单（需与前端评审）

| 项 | 变化 | 兼容策略 |
|---|---|---|
| 三频道订阅 | 语义不变（仍是 control/conversation/tool 视图） | 无感 |
| timeline wire（`Ringing_timeline_intent_v1`） | 不变 | 无感 |
| 断线重连参数 | 从 `Last-Event-ID`/checkpoint 迁移到 `since_seq` | 提供兼容映射期（旧参数→服务端换算） |
| 回放保证 | 从"断线期间逐事件可回放"改为"**最终态可由历史重建**" | **需前端确认渲染策略**（重连后重投影 vs 增量续播） |
| lease | 若保留多客户端所有权：改为内存态 + 明确移交语义（对齐 grok driver 移交） | 需评审 |
| 阻塞请求重放 | 新增：未决审批/ask/plan 重连自动重发 | 前端需幂等处理 |

### 2.5 分期

- **R1**：canonical log 合并（journal×3 → 1）+ 删除 checkpoint 目录（先双写观测，再切读，再删写）
- **R2**：重连协议改造（since_seq + 原子订阅 + 阻塞请求重放）
- **R3**：订阅状态内存化 + lease 简化/移交语义
- **R4**：offload/audit 归位；timeline 快照降级为缓存；旧目录清理迁移脚本

## 3. Agent Loop v2.0（TurnCore）

### 3.1 目标形态

Loop 只拥有三件事：**接收输入 → 驱动 lap 循环 → 判定终态**。

```rust
// TurnCore：纯逻辑，零 IO，目标 ≤ 800 行
run():
  while let Some(input) = inputs.next() {        // TurnInput 队列（四类输入统一）
    let mut turn = Turn::begin(input);
    loop {                                        // lap 循环
      let ctx = context.build(&turn);             // 纯函数（读 store + 压缩检查点）
      match gate.stream(ctx).await {              // 流式；错误分类/重试全在 gate 内
        Outcome::Tools(calls) => turn.push(tools.run(calls).await),  // 审批/沙箱/排序在 tool runtime 内
        Outcome::Text(msg)    => { turn.complete(msg); break; }
        Outcome::Suspend(r)   => { self.suspend(turn, r); break; }
        Outcome::Aborted      => { turn.abort(); break; }
      }
    }
  }
```

**三类契约**（先冻结再搬迁）：

- **进**：`TurnInput { UserInput | ToolOutput | InterAgent | SystemInjection }`（子代理报告只是其一，删除专属总线）
- **出**：`Effect { Persist | Emit | RequestApproval | SpawnTask }`，由 EffectHost 执行
- **停**：`Suspend / Cancel` 是状态机事件（取消归一：token 树 + 取消事务对象，删除三概念）

### 3.2 六类归位（判据 → 去处）

| 判据 | 拎出物 | 去处 |
|---|---|---|
| 有独立生命周期 | `engine_compact`(796) + pending_compact_* 三字段、`engine_title`(222) | 后台任务队列 / compaction 子系统 |
| 是"出口" | `paced_emitter`(127)、`emit_*` 13 处 receipt、`drain_persist_ops` 6 处、`tool_outbox`(734) | 协议适配层 / 存储层内聚（意图日志并入 store WAL） |
| 是"入口" | `injection.rs`(249) + `loop_injection.rs`(497)、`loop_dispatch_*.rs`(476) | TurnInput 输入管线 / 适配层 |
| 是"策略" | `input_guard`(130)、`state/token_calibration`(424) | 策略层 / context-gate 层 |
| 是"资源" | `liveness`(110) | registry |
| 是"会话" | `engine_session`(169) + `state/lifecycle`(365) + `init_session` | session manager |

**待拆大件**：`state/agent.rs`(1422) 拆四份（ContextBuilder / ToolMode / SessionMeta / CompactionState）；`engine_tool`(1127) 三分（执行→tool runtime、审批→sandbox/policy、展示→投影）；`loop_outcome`(578) 三分（终态→EffectHost、goal→goal 模块、compact 收尾→compaction）。

### 3.3 三条不变量（替换 ~30 个补丁）

- **I1 回合生命周期 = 类型化状态机**：非法状态不可构造（替代 ghost-lap / stale-suspension 等守卫）
- **I2 每个工具调用恰好一次终态**：执行前写 intent（fsync）→ 终态写 result；恢复 = 重放；取消 = 写终态记录（替代 outbox + seal + orphan 三件套）
- **I3 上下文合法性由构造保证**：store 写入期校验交替/配对；`build_context` 是纯函数；压缩是纯变换产新检查点（恢复 v1 ContextAssembler 的正确直觉）

### 3.4 迁移路径（行为不变优先）

- **L0**：清死代码 + 归一半成品（`LoopPhase::GoalActive`、cache diagnostics、DBG eprintln、`let _ = (&parsed,…)`）
- **L1**：抽 `TurnCore::step`，1:1 包裹现有 `run_lap`（测试不动）
- **L2**：单事件流（timeline/频道/投影全部由 canonical 事件派生，删双发点）
- **L3**：取消归一（三概念 → 状态机一等事件）
- **L4**：工具意图日志（替换 outbox/seal/orphan，故障注入证明等价）
- **L5**：协议适配层外置（Ringing 概念离开核心）

## 4. Sandbox / 权限 v2.0（概要，另立 spec）

三层结构（对齐 codex，保留我们的凭证模型）：

1. **OS 沙箱（地基）**：Linux landlock/bwrap、macOS seatbelt、Windows MXC；`WorkspaceWrite{writable_roots, read_only_subpaths(.git/hooks 等), network_access}` 形状；exec 子进程网络 seccomp 阻断（grok 模式）。
2. **规则引擎**：allow/deny/ask + 命令前缀/网络规则 + `amend`（"记住这个决定"= 追加规则）——替代"四级档位"作为日常决策面。
3. **审批升级**：沙箱拒绝后的升级路径（保留一次性凭证/trusted folder/审计）；可选 AI 审查者（codex guardian / grok Auto 分类器）。

**保留**：一次性授权凭证（不可伪造）、审计账本、子代理沙箱开关。
**第一刀范围建议**：Linux landlock + workspace-write 语义；Windows 先做进程硬化。

## 5. 附录 A：codex / grok 答案速查

| 问题 | codex | grok-build |
|---|---|---|
| 循环形态 | `tasks/`(SessionTask) + `run_turn` + `try_run_sampling_request`；循环数百行 | SessionActor(OS 线程) + `run_session` + `run_turn_via_sampler`(限流预算) + `tool_calls.rs` |
| 工具 exactly-once | 重试时 `executed_tool_calls.attach_to_prompt`（已执行结果重新附着，绝不重跑） | 结构化 ToolOutput + `wait_interrupt` |
| 权限/沙箱 | SandboxPolicy(OS 级) + execpolicy(规则引擎+amend) + AskForApproval(4 态+Granular) + guardian(隔离线程审查者) + shell-escalation(升级) | nono(landlock/seatbelt) + PermissionRule(Allow/Deny/Ask+bash 拆分+exec_risk) + PermissionMode(6 态, Auto=后台分类器) + pending_interaction(阻塞式反向请求) |
| 取消 | `tokio_util::CancellationToken` 树 + `OrCancelExt` | `cancel.rs`：CancelOutcome/WakeBarrier/CancelledTurn{epoch,reason}；含 rewind |
| 持久化 | rollout JSONL(每 thread) + writer_lock(跨进程单写者) + reverse_scanner + sqlite state_db + session_index | `updates.jsonl`(唯一事实源) + `chat_history.jsonl`(派生缓存) + 小状态文件 + sqlite(journal-mode 自适应 NFS) |
| 断线重连 | 历史投影 + 原子订阅；只重放阻塞请求；订阅内存态 | `session/load` 流式重放(单播+seq 去重)；driver 移交；pending modal 重放 |
| 压缩 | 本地+remote V2+pre-sampling+auto window；失败保留输入 | two-pass(95%→NOTE₁，重写 NOTE₁+5%→NOTE₂) + 校验/降级 + suppression 状态 |
| 注入/steering | `TurnInput{UserInput,FunctionCallOutput,ResponseItem,InterAgentCommunication}` + mailbox | `xai-interjection-core`(buffer/format) + prompt_queue + `message-delivery-core`(信封+Principal+授权) |
| 子代理 | agent registry(限额) + roles + InterAgentCommunication | subagent attempts(child_runtime/attempt_store) + 消息交付带身份授权 |
| 事件/投影 | canonical history → `thread_history_projection` 投影客户端视图 | ACP updates + `replay_events` |
| 多客户端 | app-server JSON-RPC + ConnectionId + thread/resume/unsubscribe | leader-follower UDS + session ownership + request-id 命名空间 |

**共同哲学**：内核级安全 → 小循环 → 每子系统独立 crate + 测试 → 追加日志 + 投影。
