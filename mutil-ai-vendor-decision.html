2. 为什么「自嵌库」不解决「各做一半」

vendor 改变的vendor 不改变的
依赖获取方式（path/git → 源码内联到本仓）
能直接改 SDK 源码
构建可重现（不再需要 sibling checkout）		 谁解析 wire
谁判终态真伪
谁组装 Done.raw_message
谁兜底畸形 tool call / 参数
gate 是否「忠实相信」SDK

若 vendor 之后不改职责划分，得到的是：本仓里 18,616 行 SDK + 9,413 行 gate，两套真相源同仓共存，以后更容易互相打补丁 —— 按宪法 9（禁止拧巴设计 / 为兼容写转换层）这是更糟，不是更好。

vendor 唯一真实的收益是构建可重现性（../mutil-ai 缺失就编不过、CI 必须额外 checkout 一个固定 commit）。但这是另一个独立问题：最小代价是 git submodule 固定 commit（保留独立仓与 pin、不推翻 ADR-0001），而不是把 18.6k 行拷进来。把「可重现性」和「各做一半」捆在一起，是问题定义错了。

  • 规则 21：LTS 仓用户空间不可变；vendor 等于把不可变面扩大 18.6k 行。
  • 法务：mutil-ai 为 MIT OR Apache-2.0（LICENSE / LICENSE-MIT / LICENSE-APACHE 齐全），vendor 需保留三份许可，并决定版本 / CHANGELOG / 后续上游合并策略。

5. 按宪法 3 / 4 / 9 的推荐下一步（开快车）

  1. 收尾 strangler 迁移：删掉 transport.rs 旧半边（头注明说可 deleted wholesale）；仍被引用的零星工具（RetryPolicy / SseTrace / 取消 / http_error_description）迁到 sdk_common 或由 SDK 承担。SDK 成为唯一 wire 解析方。
  2. 统一 Done 组装：四条 wire 都走「SDK 组装好的 message → harness 内容块」映射（responses 的 response_message_to_blocks 已是正例），删掉 StreamState.finalize 的自攒缓冲路径 → 消除 "not from the SDK response" 与两套做法。
  3. 兜底按宪法 5 二选一：要么上移到 SDK（在姊妹仓改 + 按规则 15 开新 LTS 线 / bump pin），要么直接砍掉让畸形 wire 如实报错；不再在 gate 里养第二套终态判别 / tool call 对账 / 参数抢救。不写防御性补丁。
  4. 保留并推广 ProviderProfile 声明式配置：端点差异以声明数据交给 SDK，不在 gate 再养一套解析器 —— 这才是「忠实相信」的正确形态。
  5. 构建可重现性单独解：git submodule 固定 commit（或 CI 统一 pin），不与「各做一半」捆绑。

这才是单一真相源，且不拆 LTS 边界。顺带一提：本仓只有 qaqh-gate 一个 crate 依赖 mutil-ai —— 收尾迁移后，gate 会薄成一层「SDK 事件 → RingingV2 StreamEvent」投影，正好符合宪法 9「任何模块为 RingingV2 让路、不写转换层」。

6. 若 owner 明确要 vendor，前置条件

  1. 写 ADR-0024：记录重开 ADR-0001 决策 5 / ADR-0018 被否选项的理由，并把「只 vendor 不改职责」列为被否选项（防重提）。
  2. owner 明确确认「mutil-ai 不再对外独立发布、只服务本仓」—— 否则 ADR-0018 的「对其它消费者可能合理」仍成立，被否理由未消失。
  3. 规则 15 分类 + 规则 18 闸门反证 + 规则 19 撞车面收敛后，再动 Cargo.toml / Cargo.lock / workflows。
  4. 保留三份 LICENSE；定版本 / CHANGELOG / 上游合并策略。
  5. vendor 后必须同步执行第 5 节的职责合并，否则只是白 vendor：18.6k 行进仓、各做一半照旧。
