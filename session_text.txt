## 两个 API 对比

| | Anthropic 端点（当前） | 原生 Chat Completions |
|---|---|---|
| URL | `/anthropic/messages` | `/v1/chat/completions`（strict 需 `/beta`） |
| 工具格式 | `input_schema` | `parameters`（JSON Schema） |
| 响应格式 | `tool_use` content block | `tool_calls` 数组 |

## strict 能解决什么

当前 400 的两个来源：

1. **schema 不规范** — `additionalProperties` 没设 false，`required` 缺字段。strict 下服务端直接拒绝，不会发到模型再报错
2. **模型乱编参数** — 模型可能发明 schema 里没有的参数名。strict 强制模型输出必须精准匹配 schema

strict 的要求：
```
每个 object: additionalProperties = false
每个属性: 必须在 required 里
不支持: minLength / maxLength / minItems / maxItems
```

## 我的建议

**值得切。** 理由：

1. 当前 Anthropic 端点工具调用就是残废的（模型出 XML），切原生 API 顺便解决了工具可用性
2. strict 是 DeepSeek 原生支持的，能大幅降低 400
3. HP 的 `client.rs` 改动集中在消息格式转换（Anthropic → OpenAI），难度可控
4. 不需要动 agent/tools/TUI 任何代码，只改 HP 的 client 层

唯一代价是 Beta 端点可能有稳定性风险，可以先不加 strict（非 Beta 端点也支持 tools，只是没 strict），先把 API 切过去确认模型能正常调工具，再开 strict。
